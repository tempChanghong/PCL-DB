# PCL-DB · PCL Download Bridge

VB.NET + WPF + .NET Framework 4.8 的 Minecraft Java 下载与本地实例管理工具，简称 PCL-DB。最新发布为 **Beta 5.0**（`5.0.0-beta.1`）。[发布说明](docs/releases/5.0.0-beta.1.md)。

Beta 5.0 后续源码修复详情“全部”筛选、取消后的滚动回写，以及前置查询期间继续操作后返回丢失筛选/阅读位置的问题；返回与分类切换也保留已展开的版本卡片。[资源页面恢复检查](docs/reviews/resource-restore-2026-10-26.md)、[前置返回联动检查](docs/reviews/dependency-navigation-2026-10-26.md)。目前仅本地提交，尚未打包发版。

详情图标现采用独立请求：分类、设置/管理和取消下载后返回会重新加载，失败可重试；已取消或失去归属的响应与缓存不再改写页面。[图标生命周期检查](docs/reviews/resource-artwork-2026-10-26.md)。

本地 ZIP/MRPACK 读取完成后，不再抢回已切走的分类、搜索或详情页；已读取的导入方案仍保留，返回导入或取消后重试可继续使用。[本地导入导航检查](docs/reviews/local-pack-navigation-2026-10-26.md)。

在线整合包与指定实例资源安装确认后，可在任务运行期间返回详情或查看管理；安装目标仍冻结。弹窗退场期间继续拦截返回，取消后恢复控件并可重试。[确认与任务交接检查](docs/reviews/task-choice-2026-10-26.md)。

安装中的可选文件确认会将焦点还给当前管理页面；刷新动画结束后再恢复，原实例消失或快速切页时不回写旧焦点。[管理页弹窗检查](docs/reviews/management-prompt-2026-10-26.md)。

“校验与补全”读取版本信息取消或失败后，会结束加载提示并允许重试；返回后重新准备时，旧请求不覆盖新状态。[补全准备恢复检查](docs/reviews/repair-recovery-2026-10-26.md)。

管理刷新发现原生实例配置损坏或运行目录变化时，旧 Mod 列表失效并停止旧扫描；修好配置后可在同页刷新，重新读取当前共享或隔离目录。[Mod 目录恢复检查](docs/reviews/mod-context-recovery-2026-10-26.md)。

Mod 文件操作期间，同目录扫描会暂缓，其他目录仍可查看；取消提示保持到操作退出，配置变化后按当前页面重新读取，避免遗留旧运行状态。[Mod 读写交接检查](docs/reviews/mod-write-handoff-2026-10-26.md)。

Mod 操作结束后重新读取所选实例配置，外部隔离设置变化无需先刷新管理列表；读取失败仍保留原操作结果，返回或改选实例会撤销旧读取。[Mod 完成刷新检查](docs/reviews/mod-write-refresh-2026-10-26.md)。

从缓存详情进入 Mod 管理时同样重读原生配置，避免有效的外部隔离变更被当作旧快照错误；保留读取失败后的同页重试。[Mod 入口检查](docs/reviews/mod-entry-refresh-2026-10-26.md)。

任务在管理页入场动画中结束时，也会完成后台刷新；手动按钮仍受输入门控约束。取消、重试或改选启动器后，旧刷新不得覆盖当前页面。[任务结束刷新检查](docs/reviews/task-management-refresh-2026-10-26.md)。

版本列表刷新失败时，当前 Mod 页也会显示错误；可直接刷新本地列表继续操作。读取中的提示和迟到结果仍按各自请求处理，下载任务结果单独保留。[刷新失败反馈检查](docs/reviews/management-failure-feedback-2026-10-26.md)。

界面、控件与动画以 PCL2 限制前源码为核心，PCL-CE 仅作补充参考。独立读取 PCL、HMCL、PCL-CE 的游戏目录与原生隔离配置；外部配置只读，已有实例设置保留。安装后的游戏继续使用所选启动器启动。

## 当前功能

- **原版与组件安装**：版本列表、官方/BMCLAPI 自动选源、并行下载、摘要校验、缓存复用、取消重试及受支持原版的已有实例补全；统一在设置中选择默认隔离策略。
- **整合包**：CurseForge / Modrinth 搜索、详情、版本选择、下载安装，以及本地 ZIP / MRPACK 导入；大型覆盖文件流式读取，不设原先的固定容量上限。
- **社区资源**：Mod、数据包、资源包、光影包的搜索、详情、版本筛选、必需前置链接、另存为及安装到指定实例。数据包明确选择存档，资源包与光影包采用实例的实际运行目录，安装后联动刷新管理页。
- **已安装版本管理**：实例列表、名称/游戏版本/加载器搜索、详情和目录快捷方式；同路径的三种启动器绑定分别处理。愚人节、远古和快照按分类显示图标。
- **本地 Mod 管理**：读取名称、版本、ID、加载器和内置图标；搜索、筛选、逐项启停及从文件安装。共享目录提示影响范围，文件与身份冲突不覆盖。
- **PCL 风格交互**：搜索分层、灰色标签、紧凑详情按钮、标题导航、逐卡片入场/返回、按压回弹和减少动画适配；快速操作退役旧动画和请求。
- **外观与设置**：三种启动器的多份目录绑定、下载及社区资源设置；主题跟随采用外部启动器卡片中的 PCL，未知或读取失败时回退，滑稽彩动态近似沿用实验性外观权限。

Beta 5.0 同时修复资源弹窗失败恢复、启动目录恢复被切页中断、手动路径误换启动器身份、恢复中设置显示/模型不一致，以及管理筛选覆盖扫描状态等问题。[管理与下载边界记录](docs/reviews/management-status-2026-10-26.md)、[输入与动画记录](docs/reviews/keyboard-handoff-2026-10-26.md)。

功能边界：受支持的独立原版可校验补全；加载器、继承版本和整合包不从管理详情直接补全。社区资源前置提供链接，尚不自动批量安装或启用光影。下载冲突、摘要不符或缺失必需文件时停止并保留诊断。

## 使用

从 [Beta 5.0](https://github.com/tempChanghong/PCL-DB/releases/tag/v5.0.0-beta.1) 下载 `PCL-DB-5.0.0-beta.1.exe` 直接运行，或下载 ZIP 解压后运行其中的 `PCL-DB.exe`。源码构建方法见下文。

Beta 5.0 的两个下载入口使用相同的单 EXE，仍需系统安装 .NET Framework 4.8。ZIP 另外附带许可、使用说明和构建清单。已有多文件预览版运行时仍须保留自己的 DLL 和配置文件。源码默认构建入口为 `src/PclDownloadBridge.App/bin/Release/net48/PclDownloadBridge.exe`，显式打包后的便携目录入口为 `dist/PclDownloadBridge/PCL-DB.exe`。

1. 打开「设置 → 外部启动器」，选择 PCL、HMCL 或 PCL-CE 的工作目录，点击「读取目录」，然后在「游戏」卡片选择安装目标；多份启动器可分别绑定，也可指定目录配置文件或手动选择 `.minecraft`。同页可分别设置「文件下载源」和「版本列表源」：BMCLAPI 优先、自动、官方优先；自动为默认值。切换版本列表源后，返回下载页会按新设置刷新当前列表；安装选项页也可点击「刷新列表」，保留版本、名称与组件选择。
2. 回到「下载」，顶部显示安装目标；点击版本，填写实例名称。展开卡片选择 Forge、NeoForge、Fabric、Fabric API、OptiFine、OptiFabric 或 LiteLoader，点击「开始下载」。按 PCL 规则显示适用选项及互斥关系，Fabric API 和 OptiFabric 随父组件显示。默认拒绝覆盖同名实例。
3. 进度在「下载」中显示。返回安装选项后可通过「查看下载进度」再次打开；切换设置保留版本、组件、自定义名称和进度。下载期间目录及传输设置只读。取消后等待连接和安装处理器退出，再返回安装选项重新开始；新任务会清空上次统计，旧回调不会覆盖本次进度或已结束的结果。
4. 完成后可点击「打开版本文件夹」查看安装结果，再回到所选启动器刷新版本列表。成功、失败和取消均可「复制任务信息」；信息和安装器日志始终对应原任务，不随之后选择的目录或版本变化。安装器日志是游戏根目录内的累计记录，未生成时按钮会禁用。若要补全已存在的同版本原版，在安装选项的「校验与补全」中明确勾选「校验补全已存在的同版本原版」。

当前源码安装组件时，不再仅凭长度复用没有上游摘要的共享支持库。若已有内容与本次私有输出不同，会保留该文件并停止发布新实例，确认冲突后可重试；原有实例及隔离设置不会因此被改写。

特供条目使用 [UVMC 补充版本清单](https://zkitefly.github.io/unlisted-versions-of-minecraft/)，行说明统一使用灰色「UVMC 特供下载」标签，并按发布时间由新到旧合入普通分类：**2.0 (Blue)、2.0 (Red)、2.0 (Purple)**进入「愚人节版」，历史快照进入「预览版」，Alpha/Beta 等进入「远古版」，不再单独设置补充栏目。先前的 12 个战斗测试版及 8 个实验快照已从补充范围移除，已安装目录保留。`rd-132211` 已由 Mojang 官方清单提供，在「远古版」中选择。UVMC 来源仍在选中提示和本文中说明，特供条目不参与最新版本推荐。补充请求独立限时 3 秒，失败仍可正常下载普通版本，点击刷新可重试；补充结果保留已有分类卡片、折叠状态和版本行，只在对应时间位置插入新条目。

三色版的列表与选中提示分别说明玩法：蓝色新增彩蛋功能、不含超级敌对模式；红色新增内容仅含超级敌对模式；紫色兼有两者。保留三个独立版本和下载身份，普通清单中未注明颜色的 `2.0` 不推断颜色。说明依据 [Minecraft Wiki](https://zh.minecraft.wiki/w/Java%E7%89%882.0?variant=zh-cn)，验证范围见[本轮记录](docs/reviews/colour-variants-2026-10-23.md)。

「远古版」中的特供条目包括 `c0.0.12a_03`、`a1.1.1`、`a1.1.0-2`、`a1.1.0-1`、`a1.0.17_03`、`a1.0.16_02`、`a1.0.14-1`、`a1.0.14-2`、`a1.0.13_01-1`、`a1.0.13_01-2`、`b1.9-pre1` 至 `b1.9-pre6`、`b1.8-pre2`、`b1.8-pre1-1`、`b1.8-pre1-2`、`b1.1-1`、`b1.1-2`、`1.0.0-rc1`、`inf-20100630-1`；「预览版」中的特供条目包含 67 项旧快照，包括 `13w12~`、`1.2`、`12w01a`、`11w47a`。归档候选中的 67 项 snapshot 已全部逐项接入，参见[旧快照阶段清单](docs/reviews/snapshot-batch-7-2026-10-23.md)；加上[首批五项 Beta](docs/reviews/beta-batch-1-2026-10-23.md)、[三项 b1.8 预览版](docs/reviews/beta-batch-2-2026-10-23.md)、[三项 legacy Vanilla 版本](docs/reviews/legacy-vanilla-batch-1-2026-10-23.md)、[首批三项显式 Alpha 版本](docs/reviews/alpha-batch-1-2026-10-23.md)及[两组 Alpha 修订版](docs/reviews/alpha-batch-2-2026-10-23.md)，累计支持 93 项补充版本。

这些条目按逐项允许表接入，保留原始版本分类，图标及日期显示参照 PCL；`b1.9-pre1` 至 `b1.9-pre6`、`b1.8-pre2`、`b1.8-pre1-2`、`13w12~` 和 `1.2` 使用已核对的独立 URL 路径映射。两个 `b1.8-pre1` 修订、两个 `b1.1` 修订以及 `a1.0.14`、`a1.0.13_01` 的两组修订均保留各自身份、客户端摘要和同日条目。两个 `a1.1.0` 修订分别保留显式 Alpha 与默认 Vanilla 启动配方，均使用各自声明的 LaunchWrapper 1.5。其余 81 项历史候选仍需逐项处理，不会按前缀批量开放，也不会重新加入已移除的战斗／实验版本。除 RC1／Infdev 与 2.0 的指定补全外，其他条目均须自带完整支持库下载信息。legacy 的 virtual 资源保留在根目录 `assets/virtual/legacy`，不随私有索引名称或实例隔离迁移。

RC1 与 Infdev 使用固定 SHA-1 校验的 Mojang `inf-20100618` 参考，仅按完整库声明匹配补齐下载信息，保留 LaunchWrapper 1.6 与 AlphaVanillaTweaker。只有这两项的 `assetIndex` 和 `assets` 都不存在时，才使用固定 PCL 的 legacy 索引；存在但损坏的字段、参考或索引下载失败均报错，不切换到其他资源树。已有外部历史实例若缺少完整声明，会提示使用新名称安装，保留原配置；新建完整实例可正常校验补全。详见 [RC1／Infdev 接入与验证](docs/reviews/early-supplemental-integration-2026-10-23.md)。

补充版本只支持原版安装及同版本校验补全，不提供加载器选择。清单中的 `2point0_blue/red/purple` 分别映射至元数据的 `2.0_blue/red/purple`，安装后的 `clientVersion` 使用后者，界面保留对应英文颜色名。普通清单中的同名或别名条目优先，补充清单中相互矛盾的重复声明不加入列表。UVMC 当前未提供这些元数据 JSON 的清单 SHA-1，因此按固定来源、已核对身份及结构检查后读取；若将来提供摘要，仍须校验通过。

2.0 的旧支持库声明缺少下载记录：本工具读取固定 SHA-1 校验的 Mojang `1.5.1` 元数据，仅对 Maven 坐标、平台规则、本机库选择及解压声明完全一致的条目补齐下载地址、大小及摘要，保留 2.0 原有的客户端、启动参数和资源索引。客户端、支持库、日志配置、资源索引及资源文件继续要求有效 SHA-1 和大小；补充版本使用按资源索引内容命名的独立索引，避免覆盖普通旧版本的同名索引。沿用现有校验、续传、复用、隔离和并行下载，不将自行计算的摘要冒充上游声明。

现有 `PCL/Setup.ini`、PCL 注册表和已有版本配置只读。隔离统一放在「设置 → 游戏 → 默认版本隔离」，下载页不再逐个选择。默认「跟随所选启动器」（下述五种隔离策略目前用于 PCL）；也可选择 PCL 的五种默认策略：关闭、隔离可安装 Mod 的版本、隔离非正式版、隔离这两类版本、隔离所有版本。默认策略只对之后新建的原版/组件实例生效；校验补全继续保留已有实例设置，CurseForge/Modrinth 整合包保持独立实例。隔离时 Mods、资源包和旧版 resources 使用实例目录；不隔离时使用游戏根目录，多个版本共用 Mods，需留意兼容性。libraries、assets 始终共享。明确指定的默认策略会在实例原子发布时保存，包括现代纯原版；现代原版跟随模式保持原有行为。偏好保存在 PCL-DB 自己的设置中，不写入 PCL 的全局配置。

共享 Mods 安装先暂存和校验，再在最终实例发布时提交；同名不同内容、文件与目录冲突及链接路径会停止安装，同内容文件保留原字节、修改时间和属性。仅最终提交期间短暂阻止共享 Mods 改写、删除或重命名，仍可读取，成功/失败均释放；下载和处理器阶段不长期锁定这些文件。最终发布失败或取消时只回收本次新增且内容仍匹配的共享 Mods/旧资源，保留原有文件和已校验缓存；普通已完成的共享支持库与资源对象继续留作复用。补全时也沿用 PCL 的已有实例分类参与默认隔离判断，不初始化或迁移已有设置。本程序偏好和日志位于 `%LOCALAPPDATA%/PclDownloadBridge/`。安装缓存和处理器日志位于所选游戏目录的 `.vanilla-downloader/`，不会删除存档。

取消时先显示等待退出状态，再通知下载和安装处理器停止。若任务随取消请求立即结束，界面保留最终结果；若实例已成功提交，仍如实显示成功。关闭窗口仅在任务仍未退出时等待，不会把已结束的任务重新显示为“正在取消”。

补充响应格式或字符编码无效时，普通版本列表仍保持可用；修复来源后可再次刷新。完成提示按实际加入的补充版本数量和分类显示，普通清单已经包含对应版本时提示「无新增补充版本」。

新装补充版本使用独立的资源索引名，避免与普通版本或其他测试版互相覆盖，实际资源文件仍共享。补全旧格式的补充实例时保留其 JSON；如果同名共享索引已有不同内容，会停止覆盖并提示使用新实例名称重新安装。缺失的旧索引及新格式实例中损坏的独立索引仍可补全。

当前源码还会检查补充版本的启动配方和对应 LaunchWrapper，提前拒绝缺少参数、错误主类、目录覆盖及冲突的 tweaker。已有实例保留自定义名称、兼容的窗口／服务器参数和隔离设置；不兼容时停止补全并提示，不自动重写 JSON。[修复范围与验证说明](docs/reviews/supplemental-launch-recipe-fix-2026-10-23.md)。

开发验证可运行 `./tools/verify-supplemental.ps1`，默认检查本批五个旧快照的在线元数据及带摘要计划；加 `-Install` 会在全新的验证目录实际下载，并检查隔离资源、发布取消／同名重试和已有实例补全。不会读取外部游戏目录作复用源，也不会启动游戏。输出包含报告和源码／进程回执；只接受生产允许表中的条目，不会自动开放其他候选。[旧快照首批接入与验证工具](docs/reviews/snapshot-batch-1-2026-10-23.md)。

## 整合包搜索与在线安装（当前源码）

## CurseForge 整合包导入（当前源码）

整合包内容不设置单文件或整包展开大小的固定上限，在线归档和 Modrinth 文件声明也保留完整的 64 位大小。覆盖内容按流提取，继续检查摘要、声明长度和目标路径；取消及安装事务保持。[大整合包修复与验证](docs/reviews/large-modpacks.md)。

下载页左侧选择「整合包 → 安装已有整合包」，在 CurseForge 卡片中点击「选择整合包」，或向窗口拖入一个 CurseForge ZIP。清单解析后显示固定的 Minecraft/Forge、NeoForge 或 Fabric 版本、实例名称及可选文件；可选文件默认不选，查询到文件名后可勾选。选择游戏目录、按需修改实例名称，再点击「开始安装」。

标题、依赖/文件统计及可选项按 PCL 控件分层显示，勾选后即时更新数量。重读 SHA-256 相同的原包会保留自定义名称、选择及已查询的文件名，更换路径的相同副本也可保留；不同内容重新初始化。先前可选择的文件在新查询失败后仍能取消勾选。保留的文件名仅用于显示，开始安装仍重新查询并校验，不能用它绕过文件缺失或摘要检查。

左侧「原版游戏」保留原有版本列表、组件安装和补全流程。切换两页会保留各自的名称、选项与滚动位置，整合包不覆盖原版已经选择的组件、隔离或补全设置。安装期间冻结侧栏与安装输入；取消后可返回相同卡片重试。读取新 ZIP 失败会保留先前的整合包；读取期间切到其他页面，结果只更新整合包卡片，不强制跳回。

页面退出或等待入场时暂停正文的键盘编辑、可选项切换和焦点进入，入场后恢复；Escape 仍可返回。跨切页释放空格不会改变复选框，也不会留下按压状态。导航与动画沿用现有页面交接，不通过禁用整页改变正常配色。

按固定 PCL 的整合包安装逻辑读取 `manifest.json`、指定 projectID/fileID 和 overrides。整合包使用新的隔离实例，不能导入已有同名实例或切换为共享 Mods；保留全局 PCL 设置和原有实例。libraries/assets 沿用共享下载，模组、资源包、光影及附带配置均留在私有暂存区，校验完成后发布整个实例目录。取消或失败清理私有载荷，已校验缓存保留供重试；包文件在安装期间只读锁定，选择后被替换则须重新选择。

导入时的单文件信息查询另有独立适配器，优先使用 CurseForge 官网公开接口，可回退 MCIM；列表源设置为镜像优先时先尝试 MCIM。配置自己的 `PCLDB_CURSEFORGE_API_KEY` 环境变量后会优先查询官方 API，密钥仅发往 `api.curseforge.com`，不写入设置、安装记录或日志。各来源的可用性随服务与网络变化，失败按上述顺序切换。必需或已选文件不存在、版本/ID 不匹配或没有可靠校验依据时，停止安装并列出错误，不替换成最新版、不静默跳过。

有 API SHA-1/MD5 时按其校验。官网公开接口未提供摘要时，仅对官方 forgecdn 地址、匹配的文件 ID/名称/长度、Amazon S3 与 SSE-S3 响应接受明确可验证的 ETag：普通单段为 MD5，`-1` 单分片为组合 MD5；弱 ETag、其他加密、多分片或未知格式直接拒绝，不能把任意 ETag 当作 MD5。实例内 `PCL/CurseForgeInstall.json` 记录原包 SHA-256、指定文件 ID、实际校验值及来源，区分 API 摘要和 CDN 校验。

实包 BetterMC 1.20.1-v1.5 声明 Minecraft 1.20.1、Forge 47.2.0 和 86 个文件。2026-10-22 已实际下载并校验其中 85 个可用文件；必需项 `227639/5071019` 当前查不到，原包导入在游戏目录写入前被拒绝。因此该包尚未通过完整游戏安装或启动验收，详细证据见 VALIDATION.md。当前不提供升级已有整合包或 Quilt 安装。

## 名称与旧版设置

项目全称为 Plain Craft Launcher - Download Bridge，简称 PCL-DB；仓库与根目录为 PCL-DB，解决方案、程序集和命名空间统一为 PclDownloadBridge。第三方独立项目身份不变。

设置中的「关于与鸣谢」参照 PCL 关于页的三列信息行：首卡列出原作者、协力开发者及本项目版本，下方分为特别鸣谢和项目与许可。三张来源头像使用固定 PCL 提交的原始资源，赞助与项目链接保持各自归属；返回按钮会恢复设置页的滚动位置。

下载、设置和关于页切换采用 PCL 源码的逐项退场、分批淡入和回弹位移；退出各项错开 15ms，进入错开 25ms，滚动条另有 90ms 移出及 350ms 移入。快速反向切页使用当前合成画面整体退场，避免错切尚未结束的画面；窗口缩放会立即完成该层动效。滚轮使用 300ms 的六次方缓动，连续输入叠加剩余位移；拖动滚动条、键盘导航或程序定位会结束滚轮动画。独立下拉框、多行文本框及可滚动子控件保留自己的滚轮操作；系统关闭客户端动画时，新页面和滚轮使用即时模式。安装页横移与卡片折叠继续使用各自的动画，不改下载任务状态。

完整版本列表返回时，用当前合成画面接入新列表入场；过期结果与隐藏列表刷新不重启当前页面动画。组件元数据刷新保留现有卡片、组件选择和入场时钟。安装选项横移同样遵守系统页面动画开关，关闭、隐藏或尺寸变化时显式收回其时钟；滚动条的鼠标、键盘及触控操作会归还稳定横向位置。

普通按钮按 PCL 叠加 80ms 快速收缩和 700ms 长按微缩，松开后延迟 10ms、用 300ms 回位；返回/清除图标以两条 250ms 曲线叠加回弹。中途重按从当前缩放衔接；页面屏蔽输入、隐藏、禁用或卸载会取消旧按压并释放缩放时钟，恢复后松开不会误触发。

版本行悬停采用 PCL 的 120ms 三次方淡入，退出先淡出再复位背景缩放；快速移入、移出及按压从当前画面接续。相同选择不重启动画，选择标记与悬停分别更新。顶部选项和版本行在隐藏、移除、禁用或屏蔽输入时也取消旧按压；重复写入顶部选项当前值不会丢掉正在进行的点击。

版本行的选中竖条按 PCL 的并行曲线弹出，取消时收缩并延后淡出，文字颜色同步渐变。快速反选保留当前高度、透明度和颜色；行高变化会更新强调色及标记尺寸，隐藏或更换主题会收束到当前选中状态。

组件卡片收起期间若列表刷新，旧内容会保留到收起结束，并停止接收点击和键盘操作，避免留下大块空白。连续刷新只保留最新列表的构建请求；提前重新展开会从当前高度接入最新内容，游戏版本、已选组件和自定义名称继续保留。

卡片标题在页面暂时屏蔽点击、标题隐藏、禁用或卸载时会取消旧按压；恢复后松开不会额外折叠，新点击照常生效。标题的有效点击高度和折叠动画仍参照固定 PCL 源码。

偏好保存在 `%LOCALAPPDATA%/PclDownloadBridge/settings.json`。首次启动先尝试迁移旧 PCD 的 `%LOCALAPPDATA%/PlainCraftDownloader/settings.json`，不存在时再读取最早的 `%LOCALAPPDATA%/VanillaDownloader/settings.json`。迁移验证 JSON 后保留原字节、编码及未知字段，旧文件不改。已有新配置优先；最新旧配置损坏或不可读时报告错误，不静默退回更旧配置。检查和预览模式只用临时样本，不迁移真实用户偏好。

游戏目录内的 `.vanilla-downloader/` 是兼容数据格式，缓存、续传、暂存、日志和安装锁继续使用，避免更名后重复安装或失去已有缓存。旧 ZIP 和历史验证记录保留当时名称。保存设置沿用互斥、深度合并与原子发布；当前配置损坏时暂停自动保存，主动保存才允许修复。

## 个性化与开发者设置

默认提供龙猫蓝、浅蓝和深蓝，可独立开启深色模式。开发者设置默认关闭，包含常规下载诊断和实验性外观验证入口。验证码通过后，其他主题直接出现在同一个个性化列表中；关闭开发者设置、重新锁定或重启会话后恢复公开蓝色选择。旧的其他主题偏好保留，锁定时不会自动应用。

代码只保留随机验证码的 SHA-256 摘要；输入及会话解锁状态不写入设置或日志。此入口用于本地功能分组，不作为安全隔离或上游额外授权的证明。

多个窗口同时使用时，外观自动保存只合并本窗口改过的字段，保留其他窗口刚保存的主题、深色模式及自定义颜色；保存失败可重试。恢复默认外观仍完整重置已知外观选项，其他下载偏好与未知字段保留。

## 功能

- 需要 JSON 对象的元数据在选源成功前检查响应类型；首选源误返回数组、空值或标量时立即尝试备用源，避免 Fabric 安装配置等请求被类型转换错误中断。组件列表仍支持合法数组，原有 SHA-1 校验和取消规则保留。
- Fabric 加载器和 OptiFine 镜像列表参照 PCL，在接受来源前检查必要字段；损坏条目会触发备用源，避免误显示空列表或把不完整版本交给安装。合法空列表、测试版标记及 OptiFine 的可选 Forge 兼容信息继续支持。
- OptiFabric 每页在选源前检查重复 ID 和必要字段，异常页可尝试相同偏移的备用源；各候选页独立检查，避免损坏来源影响后续列表。CurseForge 的零字节大小按 PCL 视为大小未知。LiteLoader 在选源前检查所选版本的安装信息，并按 PCL 忽略 `snapshot` 标记的大小写。
- OptiFabric 按 PCL 优先使用 SHA-1，未声明时使用 MD5，贯穿下载、已有文件复用及私有组件缓存；声明的校验值错误时拒绝内容，避免同大小的错误 JAR 被安装。列表中选用的校验字段无效时先尝试备用来源。
- OptiFine 按 PCL 检查文件大小：作为模组至少 64 KiB，独立安装至少 300 KiB，并保留 JAR 结构检查。首选源返回过小或损坏的文件时尝试备用来源；两个来源均不合格时停止安装，不发布残缺实例。
- Fabric API 会核对响应声明的游戏版本、加载器和项目，按实际发布时间从新到旧排列。文件选择保留 `primary` 优先；缺省时从运行用 JAR 中选择，跳过常见源码、Javadoc 和说明附件，并在列出选项前检查地址、文件名、大小及声明的 SHA-1。
- 所选 Forge / NeoForge 安装器缺少校验值时，按文件下载源设置补取 SHA1，来源失败可回退，SHA1 不可用再尝试 MD5；全部失败则停止安装，也不会仅凭已有私有缓存继续安装。已有校验值直接复用，读取过程中可取消。NeoForge 兼容 1.20.1 的旧 Maven 包名。BMCLAPI Forge 的损坏校验字段在选源前拒绝，避免错误响应阻断健康来源。
- Forge 的显示版本与 Maven 文件坐标按 PCL 分开处理，补齐部分 1.8.9、1.7.10 安装器的历史分支；刷新来源按完整安装器地址保留选择，同版本号的其他分支不会静默替换当前安装方案。
- 组件兼容判断复用 PCL 的数字及预发布版本比较规则；Fabric、LiteLoader 卡片按 PCL 的版本代际显示，避免将 `1.9-pre1` 当作高于 `1.13`，或将 `1.20.4-pre1` 当作高于 `1.20.4`。保留远古版本的独立保护，不据版本格式推断真实组件已发布。
- Forge 卡片按 PCL 的标准版本格式判断显示，兼容 `26.1` 等新编号及对应预发布形式；列表没有适用安装器时显示空状态，不据版本格式推断实际可安装性。
- NeoForge 列表按 PCL 源码区分 Minecraft 版本、显示版本和 Maven 原始坐标，识别 `1.21`、`26.1`、对应快照及愚人节版本；alpha/beta 显示为测试版。列表解析检查不等同于这些版本的完整安装或游戏启动验收。
- 读取 PCL 自定义目录时沿用用户设置的名称，并按路径合并重复项；盘符根目录保留完整的 `C:\` 形式。当前目录配置无效或被占用时报告读取问题，仍返回可用游戏目录；读取过程不修改 PCL 配置。
- 普通按钮的悬停底色、禁用灰色及高亮优先级按 PCL 源码对齐；返回图标随深色模式调整中性色。图标按钮被禁用或卸载时会清除未完成的按压，重新启用后不会把旧的松开操作当作新点击。
- Java 版本检测同时读取两路输出，较长的 JVM 环境提示不会堵住管道、误报版本不足；保留检测超时，拒绝以错误码退出的运行环境。兼容旧版 `1.8`、现代版本及 PCL 支持的无引号 OpenJDK 版本行；不会把环境选项中的版本文字当作实际版本。
- Java 安装处理器的日志被设为只读或被其他程序占用时，继续显示实时输出；日志恢复可写后继续追加。处理器自身失败仍报告退出码和末尾输出，取消仍阻止实例发布，可重新安装；不会覆盖原日志。
- 下载或组件安装失败时，在游戏目录的 `.vanilla-downloader/installer.log` 追加整组失败原因，保留各来源、重试和组件校验的诊断；任务结束后可通过「打开日志」查看。日志写入与处理器/清理记录统一串行追加，旧记录保留；日志不可写不改变原始结果，主动取消不记为下载失败。
- 版本列表与安装选项保留 PCL 的 260ms 两段横移，并叠加 MyPageRight 的可见卡片节奏：入场每项错开 25ms，淡入并从 -16 DIP 回弹；返回每项错开 15ms，淡出并上移 6 DIP。快速反向从当前画面续接，横移完成后逐项放开已显现卡片的输入，焦点恢复等待卡片尾段结束。设置、整合包和任务页交接会清理旧时钟，保留选择、滚动位置与任务。

- 组件卡片展开时，版本图标和摘要在 60ms 内淡出并下移 6 DIP；收起时以 60ms 淡入、150ms 三次方缓动返回。清除按钮保持原位；重复列表刷新不重播动画，快速反向切换从当前状态继续。
- 新选 Minecraft 版本时，安装选项回到顶部；设置往返保留当前位置。卡片短程折叠采用 PCL 的五次方缓动，长列表采用原版分段时长和曲线，箭头同步使用 250ms 五次方缓动；快速反向折叠和页面卸载会释放旧动画。
- PCL 游戏目录发现，`$` 相对路径、自定义目录去重、已安装版本数量；中文路径。
- 常规重复支持库先按规则筛选，再按 PCL 的版本比较流程选择；普通库与原生库分别处理，较旧的组件声明不再覆盖较新的同类库。指向同一文件的重复声明仍合并完整校验，冲突会报错；其他平台的条件信息继续保留。
- 支持库省略下载路径时，按 PCL 的 Maven 坐标规则定位文件；省略下载地址时使用库声明的仓库或默认库仓库。普通库与 Windows 原生库分别解析，保留明确指定的路径、地址和哈希；大小为 null 时按未知大小处理。明确写成空白的路径会报错。
- 对带 `@扩展名` 且提供 artifact/classifier 声明的库，最终配置补齐 PCL 可直接读取的明确路径和地址；Windows 原生库同时解析架构字段。原版校验补全使用同样的规范化规则，已有 JSON 保持不变。
- 可选本地副本在复制或副本校验时发生 IO/访问错误，会继续尝试其他副本，再回退下载；不将复制失败计入网络重试或已复用文件。复制前后及副本校验后检查取消，避免已观察到取消仍发布文件；真实目标写入失败仍报错。
- 对照 PCL 查找已安装客户端：搜索版本目录内所有实际扩展名为 `.jar` 的文件，允许文件名与目录名不同，校验后复制到新实例。跨目录复用至少要求上游声明大小、SHA-1 或 MD5；没有这些声明时重新下载。其他游戏目录只读，不改旧版本 JSON 或 PCL 设置。
- 下载文件通过校验并写入目标后，已知分片清理受阻不再引起重下载或误报失败。继续清理其余已知文件，并尽量将保留路径写入 `.vanilla-downloader/download.log`；日志不可写也不改变成功结果。哈希错误和真实目标写入失败仍会报错。
- 安装进入最终写入阶段后，在发布实例或替换补全客户端前再次检查取消；在此之前观察到取消时，保留原实例及已校验共享文件，后续可复用重试。已经取消的安装或空下载批次不会创建游戏目录或发送完成通知。
- 安装结束时，组件或暂存目录中的文件被占用，会保留清理未完成的临时文件，并尽量将路径写入安装器日志；成功、原始错误或取消状态保持。目录名冲突等实际写入失败仍阻止安装完成，取消后可重新开始并复用已校验文件。遗留临时目录暂不自动回收。
- 下载清单按实际保存位置去重，兼容大小写、正反斜杠及内部 `.` / `..` 写法；重复文件保留完整的已知大小、SHA-1 和 MD5 校验，避免误用同大小的损坏文件。Forge / NeoForge 的可下载安装依赖也先合并声明，再判断内嵌文件能否复用；冲突在该批依赖传输和 Java 处理器执行前报告。下载计数按唯一保存位置计算，保留第一条声明的地址及原选源优先级。
- 主页面为「管理」「下载」「设置」，沿用 PCL 的 48 DIP 标题栏、字体、方块图标。已安装版本在管理中浏览；最新版本、四类可折叠版本列表、组件选择和进度继续位于下载流程中。
- 「设置 → 关于 PclDownloadBridge」提供构建版本、复制版本信息、项目说明、PCL / BMCLAPI 源码链接与来源致谢。布局参照 PCL 关于页的卡片、圆形图标、45 DIP 信息行及右侧操作按钮；返回时保留设置滚动位置，下载中也可查看。
- 下载页「更改目录」或安装前缺少游戏目录时，直接定位到设置中的游戏目录卡片；保存设置遇到无效限速时，定位并聚焦到错误输入框。保存结果显示在按钮旁，后续编辑目录或下载设置时自动清除旧提示。
- 下载结束后保留结果位置和操作入口：成功才提供版本文件夹，失败保留 PCL 失败图标与原因，主动取消显示「已取消 / 未完成」；开始下一任务时清除上次结果。原目录或日志已被移除时就地提示，不转到后来选择的目录。
- 结果页刷新和打开操作都会复核本次任务路径；日志或版本目录被目录联接替换、路径失效或实例不属于本次游戏目录时停用对应入口，保留任务结果和复制信息。正常路径恢复后可重新启用；任务运行中忽略旧的打开操作。
- 顶部页签、折叠标题、原版及组件版本行支持键盘焦点与 Enter/空格；选定原版后定位名称输入，选定组件后返回其标题。未访问的长列表占位仍可获得焦点并按需生成该行。Esc 先关闭下拉菜单或展开卡片，再逐层返回关于页/设置/安装选项；下载中返回不会取消任务，版本浏览页的 Esc 不关闭程序。
- 原版及七类组件版本行按 PCL 的可见区域机制延迟创建：展开列表先保留完整的 42 DIP 行高度，滚动到该行后才生成图标、文字和点击处理；支持直接跳到中间或末尾，无需逐页点击“显示更多”。已访问的行继续复用，列表条目不变时切换选择只更新高亮。
- 版本分类沿用固定 PCL 的误标记补正、已知愚人节版本和 UTC+2 日期规则；四类列表按发布时间降序，最新预览版只有晚于最新正式版才同时推荐。愚人节条目使用金块及 PCL 简介，`20w14∞` 显示别名保留原始下载 ID 和校验声明；名称卡和 Minecraft 摘要随所选原版使用对应图标。
- 原版 JSON、客户端 JAR、Windows 支持库及原生库、日志配置、资源索引及对象规划。
- 独立的文件下载源、版本列表源设置，按 PCL 的镜像/自动/官方顺序排列，明确镜像为 BMCLAPI。可使用官方列表配合 BMCLAPI 文件，或反向搭配。选择表示优先级，首选失败仍会尝试备用来源；两项设置独立保存，旧版单一设置升级后保留原含义。
- Minecraft 与 Forge、NeoForge、Fabric、OptiFine、LiteLoader 等列表使用版本来源偏好；客户端、支持库、资源和组件文件使用文件偏好，OptiFine 的官方网页解析与镜像文件也按文件偏好切换。第三方资源服务使用实际可用接口，不是所有域名都存在 BMCLAPI 对应入口。
- 版本与组件列表支持取消旧请求、重复刷新和独立重试；旧来源的晚到结果不会覆盖新列表。组件同版本重新绑定最新的下载地址和校验声明，保留自定义名称及手动取消的依赖。已选组件刷新期间暂停安装；新来源缺少该版本时提示确认，不自动升级或悄悄沿用旧条目。未选组件的获取不阻塞原版安装；原版列表刷新失败时保留上次列表。
- 版本列表、组件 JSON 与网页元数据先检查 HTTP 状态和 32 MiB 字节上限，已声明过大或 HTTP 失败时立即启动备用来源；没有 Content-Length 的响应也在读取中执行同一上限，避免等待完整错误响应。保留原始字节的 SHA-1 校验、网页字符集/BOM 解码、取消及 45 秒请求时限。
- 自动选源按 PCL 的会话判定：自动模式版本列表先请求官方，5 秒后启动镜像；有效官方列表在 4 秒内完成后，本次运行的文件下载优先官方。手动优先级始终生效，未通过验证或取消的响应不改变判定；列表刷新、组件列表和安装共享判定。
- 客户端与支持库、资源分支并行；已校验的客户端和支持库就绪后可安装组件，同时继续下载资源。所有内容引擎共用连接数、每主机上限、速度预算和传输缓存锁；任一分支失败会取消并等待其他分支，全部成功后才发布实例。进度按分支汇总，多个阶段可同时显示进行中。
- 按 PCL 的文件类别区分 piston-data/piston-meta 镜像路径：资源走 `/assets`，支持库依次使用 `/maven` 和 `/libraries`，客户端及元数据保留根路径；保留官方回退与查询参数。
- PCL 100ms 速度采样、30 点加权均速、最近一秒 85% 速度基线；按最大剩余片段动态 60/40 切分，256 KiB 下限，Range 不可用时回退。
- 内容下载共享一个速度上限，普通文件与分段连接合并计费；空闲额度最多保留 100ms，取消不会拖累下一批任务。主动限速等待不计入网络无数据超时，等待期间持续更新进度并可取消。上限单位为 MiB/s，0 表示不限速，正数至少为 1 字节/秒。
- 大小/SHA-1 校验、其他已选目录文件复用、取消、分段续传、失败重试。
- 普通单连接文件也支持取消后或连接中断后的续传：仅在大小已知且声明有效 SHA-1/MD5 时读取保留的传输残片，以 HTTP Range 请求剩余部分，整文件校验通过后才发布；可跨下载引擎和安装暂存目录恢复。服务器忽略 Range 时用完整响应从头覆盖；返回错误区间或 416 时回退完整请求。损坏残片在最终哈希校验失败后清除并重新下载；无哈希或未知大小的文件仍从头下载。已完整接收但未提交的文件可校验后直接复用。进度详情显示续传保留的字节数。
- 相同资源对应多个落盘路径时协调共用缓存，避免旧版资源映射争用临时文件；明确声明或通过哈希校验的零字节资源可下载、复用；损坏的续传记录会重建，不影响缓存中的无关文件。
- 新实例全部文件成功后再提交 JSON/JAR；补全不覆盖版本 JSON 或 PCL 配置。
- 补全前核对 PCL 游戏版本、资源索引和日志文件声明；对修改过的下载声明明确拒绝，兼容未写入 `clientVersion` 的原版配置。组件只发布最终配置引用的支持库，已校验正确的共享文件直接复用；文件占用或实例提交撞名时保留已有文件，清理本次临时副本，解除占用后可重试。
- 加载器参数按顺序追加，保留重复的选项名和值；旧式游戏参数与新式条件参数并存，新增 JVM 参数时保留 PCL 的旧版 classpath/natives 默认项。支持库覆盖身份区分 classifier 和扩展名，默认 jar 与显式 `@jar` 统一，避免不同文件类型被误删。

## 构建与验证

Visual Studio 2026 可直接打开 `PclDownloadBridge.sln`，选择 **Debug / Any CPU**，将 **PCL-DB** 设为启动项目，选择同名启动配置后按 **F5**。已提供主程序、界面自检、组件页渲染及本地下载回归的启动配置；具体输出、断点建议和复查命令见 [VS2026_DEBUG.md](VS2026_DEBUG.md)。

主应用的 **Appearance Checks** 配置可独立执行 191 项主题/任务状态检查，**Card Checks** 执行 134 项卡片、摘要动画、安装视口与版本格式检查；**Navigation Checks** 执行 833 项页面切换与状态保留检查；**Settings Compatibility** 执行 49 项更名与设置兼容检查；全量界面检查为 1903 项，包含以上各组。检查在离线示例模式运行，失败保留已通过项、失败名称、异常堆栈与诊断，并返回失败退出码。

需要 .NET SDK 10.0.4xx 与 .NET Framework 4.8 Developer Pack；完整处理器样本检查还需要本机 Java 8 或更高版本。应用运行本身需要 .NET Framework 4.8。两个 Java 桥接/样本 class 已随源码保留，重编译命令为 `javac --release 8`，对应源文件在 `tools/java/`。

```powershell
.\build.ps1
```

从仓库获取完整源码后即可运行上述命令；常规构建和界面对照检查不需要在旁边另行克隆 PCL。44 份固定源码快照和 19 项资源的提交哈希清单已包含在仓库中。只有维护者重新执行 `tools/import-pcl-ui.ps1` 导入上游代码时才需要相邻的 PCL 源码仓库。

默认构建三个 VB 项目，核对 44 份固定 PCL 源码及内置资源，运行本地下载/安装、界面、动画和搜索回归，并检查验证器的回执/归档兼容规则。下载检查目录位于系统临时目录 `PclDownloadBridgeTests-<随机ID>`，不接触用户游戏目录。验证器检查只用受控回执和微型 ZIP 解析样本（其中 EXE 为文本样本），不构建单文件候选或发行包。默认不更新 `dist`，不执行完整打包回归；`-SkipTests` 可只构建。

仅在明确要求打包时执行以下命令；发版同样需要明确要求，不作为每轮修复的默认步骤：

```powershell
.\build.ps1 -Package
```

此模式独立构建单 EXE，并执行 25 项单文件、1903 项界面、1457 项动画和 1085 项搜索候选检查；完整模式另运行临时目录中的打包回归，再生成便携目录、ZIP、可单独分发的版本号 EXE 与独立构建清单。不会读取旧 bin 作为打包候选。

新 ZIP 内固定为 `PclDownloadBridge/` 下的 `PCL-DB.exe`、7 份文档（包含 `LICENCE`）和 `build-manifest.json`，共 9 个文件，无相邻 DLL、config 或 PDB。独立资产使用完整发布版本。v3 清单记录数字程序集版本、发布版本、完整提交、分支、工作区是否有改动、源码清单 SHA-256、SDK、运行时、两份内嵌依赖及每个载荷文件的 SHA-256。四组验收各自保留 Scope、Succeeded、Count、Passed、实际 EXE 摘要和单文件模式标识；当前要求由 `tools/VerificationTools.psm1` 集中维护。EXE ProductVersion 必须包含发布版本和提交；源码、文档或候选改变后需重新验证。下一次发行另定新版本，不能以新增功能覆盖既有 Beta 身份。

打包先复制已验证候选到独立暂存目录，校验四种输出后再顺序替换；旧目录、ZIP、EXE 和清单保留在报告记录的备份位置。文件占用或替换失败时逆序恢复，失败详情、回滚问题和备份位置写入 `artifacts/packages/<本次编号>/failure.json`。文件锁阻止并发打包，输出路径经过目录联接检查。这是顺序替换与尽力回滚，不保证断电或强制终止时的多文件原子性。

结果打印 ZIP、单 EXE、清单及本次 `result.json` 的完整路径，报告记录全部摘要。明确指定候选包可独立检查包内一致性及所有分发资产：

```powershell
.\tools\verify-package.ps1 -PackagePath .\dist\PCL-DB-5.0.0-beta.1.zip -DistributionPath .\dist\PclDownloadBridge -StandalonePath .\dist\PCL-DB-5.0.0-beta.1.exe -ManifestPath .\dist\PCL-DB-5.0.0-beta.1.build-manifest.json
```

上面的命令执行归档完整性检查，返回 `VerificationLevel=ArchiveIntegrity`、`CandidateVerified=false`。Beta 1.0 的 v2 清单保留当时的 25/658/328 记录，仅校验其结构、非零整数计数及实际文件摘要；不套用当前套件数量。Beta 2.0 的 v3 清单还核对四组完整回执及其 EXE 摘要。两种归档检查都不证明源码来源、签名或通过当前验收，v1/未知格式仍拒绝；旧 ZIP 不会被重写。检查旧 Beta 时请同时指定它对应的资产，不要混用当前便携目录。

以后验证新发行候选时，使用该次四项资产的实际路径，并追加 `-CandidateResultPath <该次单EXE验证打印的result.json完整路径>`。只有当前 v3 候选通过全部套件、源码、载荷及清单证据一致性核对，才返回 `VerificationLevel=CurrentCandidate`、`CandidateVerified=true`。历史回执或普通多文件 EXE 的回执不能用来通过当前候选验收。

`-SkipTests -Package` 跳过核心、常规构建回归及打包回归，仍强制独立构建并在同一个单 EXE 上执行 25/1903/1457/1085 四组候选验收，以及源码和全部分发资产校验；不能据此声称通过完整回归。单独执行 `tools/verify-packaging.ps1` 会创建全新候选，仅在随机临时目录生成测试 ZIP，不更新项目 `dist`。可用 `-CandidateResultPath` 显式复用当前源码对应的候选，避免重复构建。

单 EXE 功能可用以下命令独立验证；该命令构建开发候选，不生成 ZIP、不更新 `dist`，不创建 Release：

```powershell
.\tools\verify-single-exe.ps1
```

验证器将 App/Core 构建到本次独立 artifacts 目录，只复制一个改名为 `PCL-DB.exe` 的文件到仓库之外、带中文和空格的临时目录。依次运行单文件、界面、动画和搜索检查，并逐项核对内嵌两份 DLL 与本次构建、七份文档与源码的 SHA-256；报告保留候选路径、载荷快照、四组完整回执、EXE 摘要、源码逐文件清单及完整提交。检查使用回环 HTTP 和预览数据，不修改真实用户设置或安装游戏。

底层开关为 App 项目的 `-p:PclDbSingleExecutable=true`，通过资源嵌入和启动期程序集解析实现；常规构建及 VS Debug 仍使用独立 DLL。单 EXE 不依赖邻接 `.exe.config`，长路径设置由最早启动代码应用；系统仍须安装 .NET Framework 4.8。关于页优先打开随附或开发目录文档；缺失时从程序资源生成内容寻址的文档副本，正常模式位于 `%LOCALAPPDATA%/PclDownloadBridge/documents/`，预览检查只使用随机临时目录。单文件模式的第三方说明同时附带完整 `LICENCE`，不需要在 EXE 旁写出 DLL 或文档。

普通构建、F5 和单 EXE 验证均不会生成正式分发包。只有显式执行 `build.ps1 -Package` 才更新 `dist`；创建 Git 标签、上传资产与 GitHub Release 仍需另行明确要求。

页面、滚动与按钮动画另设 1457 项 `--motion-checks <报告路径>`，普通默认构建和单 EXE 验证均会执行，报告与上述 1903 项界面检查分别记录。VS 可直接选择 Motion Checks；该入口使用隔离预览数据，检查曲线、快速导航、关于页的焦点/返回交接、高频滚轮、展开时滚动、缩放换行的高度衔接、裁剪区域中的延迟行及按钮按压/回弹和中断清理，并输出采样帧，不是桌面帧率测试。

维护固定 PCL 参考时，先执行以下检查（需要本地 PCL Git 对象，可用 `-SourceRoot` 指向没有检出文件的仓库）：

```powershell
pwsh -NoProfile -File .\tools\import-pcl-ui.ps1 -CheckOnly
pwsh -NoProfile -File .\tools\verify-pcl-import.ps1
```

导入器的源码、图片、字体和 `LICENCE` 全部取自固定提交 `5ef81e4` 的 Git 对象；上游当前分支和工作目录的变化不会成为导入内容。去掉 `-CheckOnly` 后仅补充缺失文件，已有 7 个控件/配色/图标适配文件始终保留；固定参考或资源与目标不同时，默认报告冲突并停止。确认报告后可使用 `-ReplaceChanged` 替换这些固定文件，原内容保存在本次操作的 `previous/`，写入失败时尝试回滚。有效清单的原始字节、未知字段及本地额外参考文件继续保留。

`-CheckOnly` 不改写源码、参考、资源或许可文件，但会在 `artifacts/pcl-import/` 写入暂存候选与报告。它不判断已有控件适配是否符合界面要求；该部分由 `verify-pcl-ui.ps1` 检查。导入回归使用独立临时项目和共享 Git 对象的临时仓库，不修改上游工作目录；因需要上游 Git 对象，不纳入普通构建的默认检查。导入采用逐文件替换与回滚，不保证断电或强行终止时自动恢复全部文件。
