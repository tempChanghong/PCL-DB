# 本地 Mod 元数据刷新与选择动画

基线：`a6ae4a9`。继续检查快速选择、在线更新结果与列表动画的联动，确认标题配色变化和选择状态变化仍被同一条入口当作完整选择动画处理。

## 依据与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `MyLocalModItem.xaml.vb`：`Checked` 对相同选择状态直接返回，`Refresh` 独立更新元数据、标题与图标。原始 Git 对象及 SHA-256 见 `artifacts/local-mod-metadata-motion/source/manifest.json`。

PCL-DB 的在线更新读取在接受结果后，通过 `SetUpdateInfo` 更新现有行的 `HasUpdate`。当用户已经取消勾选、竖条正在退出时，这会改变标题目标色。原选择动画入口同时比较选择状态和颜色键；仅颜色变化也会移除原时钟，并从当前高度重新开始 120 ms 的收缩及延迟淡出。结果是退场拖尾、原时钟无法完成清理。闲置的未选中行收到同类信息时，也会创建高度始终为零的选择动画。

## 修复

在可播放动画的入口中，先判断选择状态是否改变。仅配色变化时复用已有的配色刷新方法，不替换竖条高度／透明度时钟；没有选择变化的闲置行也不创建选择时钟。自然完成时仍以最新颜色键恢复资源引用。

保留 PCL-DB 对可更新文件的强调色，以及启用、禁用、选中、深色模式的现有规则。真正勾选／取消勾选时继续使用原 PCL 曲线、时长及当前帧采样；隐藏、离页、关闭动画和动态主题的清理机制保持。未修改在线查询、文件校验、安装、隔离或外部配置逻辑。
