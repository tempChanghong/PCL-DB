# 完整验证清单的默认打包修复

基线：`e2acdd8062f62bdea6bcb23824b2baad8417edd5`（Beta 7.0）。

## 问题与复现

发布时已使用进程级紧凑 JSON 默认值完成 Beta 7；工具代码仍默认写入带缩进的清单。因此普通调用会将全部界面、动画、搜索断言序列化成超过 1 MiB 的清单，并被自己的 ZIP 校验拒绝。发行工件本身不受影响。

本轮读取真实 Beta 7 清单：同一对象的缩进 JSON 为 **1,070,030 字节**，紧凑 JSON 为 **964,016 字节**。私有临时 ZIP 复现旧格式的 `Oversized build manifest`，原发行文件摘要保持。

另在既有验证契约中加入完整回执夹具，先将生产写入语句仅提取为私有函数，保持旧写法运行；新增检查在实际写入尺寸处失败。保存的基线探针及失败回执见 `artifacts/manifest-serialization/baseline-probe.patch`、`before.json`。这是工具序列化复现，不是应用运行结果。

## 修复

- 生产写入显式采用紧凑 JSON，保留全部断言、嵌套字段与原序列化深度，不再依赖调用者或模块的临时默认值。
- 固定 UTF-8 无 BOM、无额外换行，使 PowerShell 7 与 5.1 使用相同的字节边界规则。写入器与归档读取器共用原有 1 MiB 上限；真正超限时在打开目标文件前拒绝，保住已有文件。
- 打包回归的清单篡改夹具也使用紧凑 JSON，确保检查缺失断言、错误来源等问题时能命中预定校验，而非先被格式空白触发大小错误。

附带回归在新的 PowerShell 进程中复现限时验证脚本的递归溢出：`Get-Command` 保存的导入 `FunctionInfo` 会在同名测试替身声明时原位改变，替身再次调用该引用就调用了自己。改为预先保存原模块绑定的 `ScriptBlock`，继续通过原有测试替身检验调用方传入的时限，不改任何实际时限值。失败日志保留为 `artifacts/manifest-serialization/timeouts-before.log`。

## 本轮验证

- PowerShell 7 / Windows PowerShell 5.1 各通过 **110 项验证契约**，其中新增 13 项覆盖完整断言往返、中文与转义、精确 1 MiB、UTF-8 字节超限、拒绝时保留旧文件／不生成半成品，以及归档读取边界。
- 真实 Beta 7 清单复查 3 个场景：生产默认写入后的临时 ZIP 完整性通过；旧缩进格式按预期被拒绝；删除原动画断言后仍被拒绝。另检查全部验证内容与原候选绑定，未把临时 ZIP 声称为当前源码的新候选。
- 验证进程通过 19 项；修复后的限时工具在 PowerShell 7 / 5.1 中各通过原有 44 项。固定 PCL 来源／资源检查通过，44 份固定源码摘要保持。
- 以 `artifacts/manifest-serialization/validation.json` 及提交后的绑定回执为准。

改动限于 PowerShell 打包工具及其验证夹具。此次不重跑应用 Core、WPF 界面、动画、搜索全套或完整候选打包回归，不复用旧结果作为本轮新通过量；未生成新产品发行、修改现有 Release、推送或向游戏目录写入。
