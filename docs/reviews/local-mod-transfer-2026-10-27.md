# 批量 Mod 更新的下载限速与确认联动

基线：`9da6e22`。检查 Mod 管理的更新按钮到下载器的参数链，发现设置中的 MB/s 直接传入以字节/秒计量的更新器。填写 8 会传入 8 字节/秒，而 0.5 因 VB 的整数转换变成 0，意外取消限速。普通游戏和社区资源下载已有换算，问题位于批量 Mod 更新入口。

## 源码依据与修复

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModNet.NetTaskSpeedLimitHigh`、`PageSetupSystem` 和 `PageInstanceMod.UpdateMods`。PCL 将界面的 M/s 数值乘以 `1024 × 1024`，网络预算按字节扣减；更新先确认、冻结清单，再构造下载。本工具沿用该换算、现有确认窗口和文件校验／备份流程，保留自身 0 表示不限速的约定。原始 Git blob 与 SHA-256 见 `artifacts/local-mod-transfer/source/manifest.json`。

仅在调用更新器之前将有效限速换算为 `Long` 字节/秒，与原版、整合包、社区资源下载一致。内部更新器调用使用可替换委托，与既有本地导入、启停和更新查询的检查方式一致；默认直接调用原更新器，没有增加用户选项。下载预算、并行分配、缓存、原子替换及备份实现未改。

## 验证

实际调用“更新所选 Mod”事件及所属确认窗口，明暗主题 × 开关动画，覆盖 0.5 MB/s 取消、同值重试、8 MB/s、0 不限速。明暗夹具分别采用 en-US、de-DE，检查小数点／逗号解析；受控安装委托记录真正传出的实例、清单、源策略、并发及限速，不进行公网下载或文件写入。

68 项专项：原行为 56 项通过、12 项失败；原始参数记录确认 0.5→0、8→8。修复后 68 项全部通过，实际参数分别为 524,288、8,388,608 字节/秒。还检查弹窗退场前不开始传输、操作中不重复确认、取消令牌、完成后刷新与再次操作，以及夹具游戏／配置的全部字节保持。管理页内容动画在每次操作后显式完成，避免把上次未完成的测试画面当作新一次输入。

专项接入 all、navigation、motion；策略 `PCL-DB-checks/2026-10-27.4`，all 2,442、motion 1,912、navigation 1,288（包含在 all）。搜索套件保留 1,481 项。各套件有重叠，不累加。最终以 `artifacts/local-mod-transfer/validation.json`、各组报告和构建日志为准；固定 PCL 来源／资源及验证契约另验。

本轮不改 Core 源码，不重跑完整 Core 套件；控制下载委托验证 UI 至更新器边界，不声称验证公网实际吞吐或完整游戏下载。离屏 WPF 真实时钟检查不代表人工桌面帧率／所有 DPI 验收。未改用户目录、外部配置、版本隔离及共享目录策略；不打包、推送或发版。
