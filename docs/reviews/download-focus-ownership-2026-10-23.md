# 下载页面动画与焦点请求的联动修复

日期：2026-10-23。基线：`a6f312f`。验证后本地 Commit，不推送、打包或发版。

## 已复现的问题

返回搜索页或从设置返回下载页时，页面会先恢复交互，卡片仍在逐项入场。原有延迟焦点恢复只等待动画完成，没有保留最初请求的焦点状态，因此用户已经选中结果行后，完成回调仍会把焦点移回默认控件。

先增加回归检查，未修复版本在 `category completion preserves a newer result-row focus` 断言失败。随后验证只比较焦点对象的修复仍不充分：搜索框可能从前一页面就持有逻辑焦点，返回后继续输入时对象没有变化，但用户已经开始操作。该中间实现又在 `typing into the same logical focus target` 断言失败。两次失败均保留独立二进制摘要和报告，不把中间实现的结果混作基线证据。

## 固定 PCL 源码依据

重新读取本地 Git 中未限制版本提交 `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的文件：

- [FormMain.xaml.vb](https://github.com/Meloong-Git/PCL/blob/5ef81e490ae46b1100d61e33d0183094c7a80ca8/Plain%20Craft%20Launcher%202/FormMain.xaml.vb)：PageChangeAnim 停止旧页面切换动画，退出后 110 ms 更换容器，再延迟 30 ms 调用 PageOnEnter；避免不同页面动画重复触发进入逻辑。
- [MyPageRight.vb](https://github.com/Meloong-Git/PCL/blob/5ef81e490ae46b1100d61e33d0183094c7a80ca8/Plain%20Craft%20Launcher%202/Controls/MyPageRight.vb)：TriggerEnterAnimation 在卡片入场开始时就恢复 IsHitTestVisible，随后继续淡入和位移；卡片逐项延迟 25 ms。退出时关闭控件命中，动画结束后才隐藏内容。

因此本轮保留入场期间可交互的时序，不延长输入门控。以下焦点请求管理是适配本项目 WPF 页面和三类动画控制器的实现，没有声称它是 PCL 源码中的同名机制。固定文件、Git 对象核对及 SHA-256 保存在本轮证据目录。

## 修复与冲突处理

每次请求记录下载视图、整合包模式、原有逻辑焦点和有效输入序号。请求经过根页面、分类页面或原版安装页的动画控制器时，传递同一个委托，不在完成时重新创建默认请求。目标已离开下载页、已切换视图／模式、关闭中或在线确认仍占用页面时，不执行原焦点恢复。

用户已经选择另一个可见、可交互的焦点控件，或者在原控件收到新的有效键盘／鼠标输入时，保留用户的选择并消费原视口恢复标记。被动画门控拦住的输入不增加序号，避免隐藏控件意外取消正常恢复。没有新操作时，仍按上一轮的策略恢复滚动视口、安装输入或任务控件。

切换设置／关于页、切换下载视图及关闭时清空分类焦点请求及委托引用。版本清单刷新需要重新生成卡片时，转交原请求，继续使用原先的焦点和输入保护；反复刷新不把用户刚选中的工具栏控件当作新的默认恢复起点。

没有修改动画曲线、持续时间、下载源、安装器、版本隔离和原子发布流程，沿用现有任务与选择状态。
