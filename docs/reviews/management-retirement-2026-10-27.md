# 管理刷新与目录动作：取消后的请求交接

基线：`dc9027e`。检查管理、Mod、下载的异步联动后，本轮收敛到管理刷新及详情页“打开文件夹”链路。原生配置、隔离策略、共享目录解析和文件安装实现不变。

## 复现与源码依据

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModLoader`、`PageInstanceMod`、`FormMain`。`ModLoader.State` 先更新 `_State`，再通知 `CancellationTokenSource.Cancel()`。本工具的管理读取使用异步任务，因此需要补充请求身份和代次校验，沿用这一状态顺序，不宣称是上游接口。三份原始 Git blob 与 SHA-256 记录在 `artifacts/management-retirement/source/manifest.json`。

受控取消回调中，实际启动新的目录动作或管理刷新，复现以下问题：

- 旧目录请求的取消通知已启动新的目录读取，旧清理随后清空新“正在读取文件夹”提示。
- 旧扫描取消通知启动新扫描，旧清理随后将请求槽位、扫描标志清空，使新读取失去取消归属和加载门控。
- 目录取消通知启动新扫描，外层清理重新读取全局请求，误将新扫描取消；其结果无法正常提交。
- 仅修清理顺序仍不够：外层旧目录点击或刷新在取消返回后继续启动自己的读取，覆盖通知期间更晚发起的操作，并造成重复请求。

## 修复

管理父请求和目录请求的旧引用、代次、标志和提示，在任何取消通知之前统一退役。取消只针对捕获的旧对象；目录取消通知异常时，也仍会通知旧父请求。目录动作的独立取消沿用同一退役函数，不再在通知后清理新提示。

目录按钮与管理扫描入口在取消前保存预期代次，取消返回后检查该代次；已被新操作替代的外层流程直接退出，不再重新分配请求或启动重复读取。扫描同时复核当前目标和页面，保留已有的迟到结果检查。

动画、焦点、目录读取校验和结果渲染方式未改；请求成功、取消与重试仍通过原流程。
