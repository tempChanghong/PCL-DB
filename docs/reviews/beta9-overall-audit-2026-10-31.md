## 已确认问题与修复

旧选择调用在动画使能回调中同步接受了新页面后，仍可能继续按旧选择配置可见性和输入状态，或创建旧动画。界面层以选择代次识别失效调用；Finish 也会使旧调用退役。相同选择的原提前返回语义、100 ms 隐藏和 260 ms 主页面交互时序保留。

四个动画属性的清理与挂接也可能同步触发属性通知；通知接受新时钟后，旧操作继续 detach/attach 会破坏新通道。专用 C# 执行器单独记录操作代次，在可能重入的步骤后检查当前所有权；普通无重入的 Stop 仍按原顺序清理四通道，包括没有所属时钟的情况。界面代次负责逻辑选择，执行器代次负责时钟与属性写入，二者不替代卡片自身的输入和高度动画。

相邻检查还实际复现了卡片内部重入：Opacity 通知中反向切页会修改正在枚举的集合并抛异常；RenderTransform 通知中反向切页会留下旧卡片动画和透明内容。卡片编排加入独立的退役检查、快照遍历和包装/回收所有权保护，不能只在外层页面调用结束后判断。保留原 Binding、局部输入值和原始变换引用，已接受的新卡片操作不被旧清理覆盖。

最终新增回归入口为 20 项，只注册组合入口，子检查不重复计数。此前试图用同值属性挂接触发通知的两个夹具未真正触发回调，原失败产物保留且不冒称运行覆盖；真正的新增卡片场景分别触发 Opacity/RenderTransform 通知。未修复 EXE 与修复 EXE 使用同一场景配对复测，原始记录与一次覆盖后重新取得的观测明确区分，不以重跑结果伪装首次记录。

旧 `edc6250` 生产代码只注入同源新测试后，分别在使能回调和通道清理重入的第一项断言失败；旧 EXE、测试摘要及原始失败回执保留。修复在同源检查和最终完整矩阵中验证，不把源码推断冒称运行复现。

实际参考固定 PCL2 `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 PageDownloadInstall、MyPageRight、ModAnimation、ModNet 和本地资源加载代码；C# 参考固定 PCL-CE `915ac29795efbdf6373417389e181e1504117048` 的对应动画、ModComp 和 ModModpack。保留 PCL2 的视觉/时序为核心，不整体引入 PCL-CE 状态机或改变加载器更新策略。

## 发布门槛与边界

版本、HTTP User-Agent、当前下载链接及 VS 2026 说明同步至 Beta 9。文档中的当前候选数量改为引用验证策略，避免沿用旧版固定计数。Beta 8 以前的报告和发行保持历史含义。

最终源必须是干净提交；同一个单 EXE 完成冷启动、完整 UI、motion 和搜索组，并核对三份嵌入依赖、七份文档与源码。完整 Core 使用同一候选的 Core 字节；用户提供的 ZIP/MRPACK 大包仍只读。打包回归显式指定候选结果，分别在 PowerShell 7 与 Windows PowerShell 5.1 执行；源码 ZIP 在仓库外解压、核对 Git blob/合法换行差异并实际构建。附件包含构建清单、验证摘要和 SHA256SUMS，发布后从公开 URL 下载复核。

审计预构建的七组 Core 定向检查与源码审查只是检查证据，不代替最终候选验证；各套件有重叠，不合计为独立场景。隐藏 WPF、受控回调与模拟网络不证明真人桌面帧率、持续平台可用性或完整游戏启动；没有对所有 Mod/加载器组合做穷举。详细执行结果保存在本地 `artifacts/beta9/`、`artifacts/beta-9.0-release/` 和发行附件中，不修改用户实例或外部启动器配置。
