# 取消入口：先停止，再访问缓存与整合包文件

基线：`ee7c195`。本轮检查整合包导入、资源下载和 Mod 更新共用的归档链路，修复已取消请求在入口处仍访问文件系统的问题。

## 依据与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModLoader.LoaderTask` 和 `ModModpack`。上游区分取消与失败，拒绝已取消／替代线程的结果，整合包按清单类型分派安装。本工具使用 Task／CancellationToken，新增的归档获取与识别接口也需要保持这个边界；不是复制上游同名方法。原始 Git 对象和 SHA-256 见 `artifacts/archive-cancellation/source/manifest.json`。

原实现的两个公共入口存在问题：

- `ModpackArchiveInstaller.AcquireAsync` 在检查取消前完成地址／路径准备并创建缓存目录。进入时令牌已经取消，仍可能留下空缓存；缓存路径被普通文件占用时，先抛出 `IOException`，覆盖取消语义。
- `ReadPackage` 在格式检测后才进入有取消检查的具体解析器。缺失文件、损坏 ZIP 会在检测时抛出文件／压缩包异常，绕过后续取消检查。

在未修改生产代码时构建新增夹具，得到 **22/31 项失败**：20 条缓存路径检查和缺失／损坏包的两条取消语义检查。正常包最终进入解析器后仍能收到取消，故这两条原本通过。结果保留在 `artifacts/archive-cancellation/baseline.log`。

## 修复

在两个入口最前方检查调用方令牌，已取消请求在复制元数据、创建目录或格式检测之前退出，异常保留原令牌。生产代码只增加两处取消检查。

进入时未取消的请求继续原有地址限制、下载锁、摘要／大小校验和缓存复用；格式检测、安装隔离、共享 Mods、文件事务及已有目标保护不变。未调整 UI、动画曲线或外部启动器配置。

本轮解决的是**进入接口时已经取消**的边界。保留执行中各阶段既有取消检查，不把这两处入口检查描述为文件系统操作可被瞬时中断。
