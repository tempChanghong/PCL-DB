# 构建与单文件验证：动画检查限时漂移

基线：`60bfcc1`。审查验证链路时发现实际阻塞：上轮 `artifacts/mod-write-start/regression-runs.json` 的动画检查正常通过，共 2,332 项、耗时 236,971 ms；`build.ps1` 和 `tools/verify-single-exe.ps1` 却仍对除 all 外的界面模式使用 180 秒。两者会在正常动画套件完成前终止进程，影响默认构建验证和后续候选验证。

## 修复

`Get-PclDbCheckPolicy` 增加有限的 `TimeoutSeconds` 元数据：all 和 motion 为 600 秒，其余界面模式为 180 秒。两个调用入口直接转交该属性，不再各自维护条件表达式。核心夹具仍为 900 秒，通用进程启动器的默认 180 秒及 1～3600 秒参数范围不变。

检查项目、计数、模式、执行顺序、退出码、新报告／预览要求、程序哈希和历史回执接收规则均保持。计数与必需套件没有变化，策略 ID 仍为 `PCL-DB-checks/2026-10-27.8`；新增限时仅控制执行过程，不写入历史回执或改变候选格式。

本轮不改 PCL2 风格的 UI、动画或下载安装代码。固定 PCL 的源码／资源核对继续由原 `verify-pcl-ui.ps1` 执行，不宣称上游定义了本工具的限时接口。

## 验证

新增 `tools/verify-verification-timeouts.ps1`，纳入默认构建的验证前置步骤。共 44 项，原实现 17 项通过、27 项失败；修复后检查通过。覆盖所有已有界面模式的有限预算、未知模式拒绝、两入口的真实策略查询／进程调用表达式、模式及输出路径保持、核心和通用默认限时保持。

调用检查解析实际脚本 AST，在进程记录替身下执行策略赋值与启动表达式；为每次调用注入不同预算，防止硬编码常量碰巧匹配。动态表达式按原脚本路径恢复 `PSScriptRoot`。不执行两个脚本的构建、单文件生成或打包主体，不启动应用；因此该检查不是冷启动单 EXE 或整包验收。

分别使用 PowerShell 7 和 Windows PowerShell 5.1 运行新检查、原验证契约及进程检查。进程检查会真正验证失败、旧输出拒绝、超时后只结束自身进程、保留另一同名进程及重试；PCL 固定来源／资源另验。

以当前普通构建程序单独运行 motion，传入新策略返回的 600 秒，严格核对 2,332 项及程序 SHA-256。App、Core、测试业务源码均未改；all 2,862／pack-search 1,481 的上轮回执只作背景证据，本轮不将其冒充重新执行。最终结果与当前工具源码清单见 `artifacts/verification-timeouts/validation.json`。

不生成单文件候选、不运行完整冷启动单 EXE 验证、不打包、推送或发版；不操作用户游戏和外部配置。限时仍然有界，不保证任何负载环境下都能在固定时限完成。
