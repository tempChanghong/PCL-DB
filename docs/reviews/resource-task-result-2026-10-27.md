# 普通资源任务：展示目标文件，区分计划与成功发布

基线：`b1283a7b380ca81ebabd028fd62d616a4d706a19`。检查资源下载任务结果时发现，`RunResourceSaveAsync` 将资源缓存目录传给通用任务结果初始化；通用面板因而把缓存显示成“游戏目录”，复制信息还包含“实例位置：未发布”。失败／取消时没有记录目标文件，不利于定位和重试。

## PCL2 源码依据

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `PageDownloadCompDetail` 保存资源流程，以及 `ModLoader.State`。上游先由保存对话框确定 `Target`，以其文件名构造资源下载任务并将该目标交给下载器；资源使用状态提示，取消先变更加载状态。PCL-DB 的结果面板是额外实现，不声称上游具有相同的复制信息或日志按钮。

两份原始 Git blob 与 SHA-256 保存于 `artifacts/resource-task-result/source/manifest.json`。

## 修复

- 开始资源任务时冻结规范化的目标文件路径，保留到成功、失败或取消后。页面位置和复制信息使用“目标文件”，不把缓存解释成游戏目录，也不声称在发布 Minecraft 实例。
- 计划目标与成功文件分开：`_taskResourceDestination` 保存尝试位置，既有 `_taskResourceFile` 仍只在任务成功后赋值。失败和取消不启用成功文件操作；打开文件夹仍要求成功文件存在且可访问。
- 本工具的 `ModpackArchiveInstaller.AcquireAsync` 将资源缓存根传给 `DownloadEngine`，其诊断日志确实位于缓存的 `.vanilla-downloader/installer.log`。因此保留这个入口，但资源任务显示“打开下载日志”，说明其是资源下载缓存的累计日志，不再称为游戏目录的安装日志。新的原版／整合包任务仍按既有重置逻辑清空资源字段，恢复安装器日志说明。

不改变下载、校验、发布事务、共享目录与原生隔离设置。页面与卡片动画参数不变，位置文字沿用原有自动换行布局。
