# 组件整批取消：先退役状态，保留新操作与页面

基线：`c83c5a672832566afbf8dbfed2d0696c53948c19`。沿上一批组件单项重试继续检查整批取消、来源切换及版本初始化，发现共享状态的清理顺序与调用者继续执行的问题。

## 源码与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModLoader.State/IsCanceledWithThread` 和 `PageDownloadInstall.EnterSelectPage/ReloadSelected`。上游先改变加载状态再通知取消，依据当前执行身份拒绝旧工作，并显式防止组件展示重入。两份原始 Git blob 与 SHA-256 保存在 `artifacts/component-retirement/source/manifest.json`。

通过真实旧组件令牌的受控取消通知，调用现有单项／整批刷新、版本选择、来源选择和窗口关闭入口，复现：

- 旧循环取消完毕后才清空共享请求与等待集合，把取消期间新登记的 Fabric 请求一并摘除，使其结果失去归属。
- 整批刷新在取消返回后仍继续启动另一批查询，覆盖更新的单项读取。
- 选择原版 B 时，取消期间已经选好 C 并修改名称、组件；旧 B 的初始化恢复后又按共享字段重建 C，丢失后选页面状态。
- 来源变更后已完成新来源查询，旧外层处理又将其标成待刷新，使已验证组合重新被阻止安装。
- 一个取消观察者异常使循环中断，后面的 NeoForge 等请求没有收到取消，关闭流程也会异常退出。

## 修复

整批取消先捕获旧请求、更新组件代次并摘除共享归属与等待状态。随后绑定新上下文，最后在 `Finally` 中逐一取消旧对象；每个观察者异常独立处理，生产环境记入已有日志，不阻止其余旧对象退役。请求仍由所属加载器在退出时释放，不释放新读取。

整批刷新和来源切换在通知返回后核对操作修订号，过期外层入口不再创建查询或改写新状态；独立组件结果仍按各自请求判定，不用该修订号串行化并行加载。来源的待刷新状态在通知前发布，新来源查询可接管并清除它。

版本初始化拆出原卡片构造步骤，在通知旧请求前准备所选原版的视图、选择状态和初始读取。返回后核对原版及所建卡片身份，已被替代的初始化使旧选择入口停止，不再重建或滚动新页面。关闭后也拒绝新的原版选择。

卡片几何、折叠曲线、依赖兼容、100 秒组件限时及原安装事务未变；不修改外部启动器、隔离设置或用户游戏文件。
