# 任务页入场失败后的显示恢复

基线：`08cb47ec9a62aab5173c88c77456ce27533637b8`。

## PCL2 依据

重新读取固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的三份 Git 原始文件，摘要见 `artifacts/task-page-recovery/source/manifest.json`。

- `MyPageRight.PageOnForceExit` 停止旧页面动画，并明确隐藏内容、加载卡片和常驻区域。
- `FormMain.PageChange` 的任务管理分支选择任务页面；标题层与返回栈随已接受的子页面更新。

本轮沿用 PCL 风格布局、标题栏和原有动画时序，补齐失败路径的可见状态恢复。

## 复现与修复

上一轮已把安装启动的异常纳入任务边界，但 WPF 可见性通知可能在页面发布中途报错：逻辑状态已是进度页，结果动作也可用，旧整合包页面却没有收起，侧栏、工具栏和返回标题仍属于旧页面。截图可见两个页面叠加；返回或切换页面才间接消除。

- 任务结束后检查进度页及其他下载页面的可见状态、侧栏和工具栏。
- 仅当当前逻辑页面仍为进度页、没有活动切页时钟且未在内容事务中时，复用当前页面发布逻辑补全显示状态。
- 其他已接受页面、正常入场／退场时钟继续保留。恢复异常单独记日志，保留原任务结果与诊断。
- 不改变下载、组件安装、共享文件发布、隔离策略和外部启动器配置。
