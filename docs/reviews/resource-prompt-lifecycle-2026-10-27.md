# 资源安装弹窗的取消与结果归属

基线：`75621ac7ecb5ee60a5d46f1c89ce7fa3a8b47a34`。本轮检查 Mod／数据包／资源包／光影包共用的指定实例安装弹窗，修复重复打开、取消时重开和迟到确认结果的关系；保留前一轮弹窗动画、下载安装、版本隔离、共享目录和外部设置。验证后仅本地 Commit，不打包发版或推送。

## 依据及复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `MyMsgSelect`、`MyMsgText` 和 `PageDownloadCompDetail`。原始 Git blob 与 SHA-256 在 `artifacts/resource-prompt-lifecycle/source/manifest.json`。PCL 先用 `IsExited` 确定消息结果，再处理关闭和退场；本项目的异步请求退役及返回计划绑定是补充实现，不宣称上游提供了同样的异步 API。

三类问题均可重复复现：

1. `PromptResourceTargetAsync` 在通用弹窗拒绝第二次打开之前，已经覆盖资源类型、请求和下拉列表。因此，被拒绝的调用仍能清空原选择，甚至把实例命名弹窗的校验改成资源目标校验。
2. 关闭先通知存档／目录请求取消，再清空弹窗结果任务和父请求。取消回调同步重开时，会被残留的旧弹窗拒绝；即使回调已经替换请求，旧关闭还会读取全局字段，取消或关闭新的选择器。
3. 确认结果的异步返回读取全局 `_confirmedResourcePlan`。把第一轮返回续体暂挂、完成下一次确认再释放，第一轮会返回下一次选择的计划，或丢失已经确认的结果。

## 修复

- 入口先检查已有待确认的弹窗，再初始化任何资源状态或控件，保留原来的拒绝策略。
- 关闭先捕获并退役旧弹窗、父请求和存档请求，开始所属退场，再通知捕获的请求取消；取消后不再读取全局请求字段。即便取消通知抛出异常，也继续取消旧父请求并完成旧结果任务，不留下永久等待。
- 每次选择持有独立的确认计划。迟到返回只读取自己的计划；旧 `finally` 只清理仍属于自己的字段，不能覆盖新选择器。
- 动画曲线、遮罩交接、退场等待与焦点恢复沿用前一轮实现。原生目标与计划校验仍由已有安装内核处理。

## 验证

三种启动器 × 明暗主题 × 开关动画，共 12 组受控状态组合。原行为先执行 144 项检查，其中 60 项通过、84 项失败；修复并补充取消通知异常检查后，168 项专项全部通过。专项接入 all、navigation、motion 和 pack-search。一个已有检查只把“未确认计划”的读取位置改为当前选择对象，原校验断言保持不变。

策略 `PCL-DB-checks/2026-10-27.2`：all 2,230；motion 1,700；pack-search 1,337；navigation 1,076 包含在 all 中。计数有重叠，以 `artifacts/resource-prompt-lifecycle/validation.json` 和各分组回执为准。固定 PCL 来源／资源、97 项验证契约及构建另行检查。

测试使用临时实例、真实原生配置读取、受控取消回调和延迟续体，不发起下载。逐字节核对实例、存档和三种启动器配置，确认没有启动安装任务。Core 下载及文件发布源码未改，本轮不重跑其完整套件；离屏 WPF 与可定位时钟不等同于人工桌面帧率或全部 DPI 验收。基线失败回执及中间状态保留在同一 artifacts 目录。
