# 本地 Mod 多选、更新与 PCL2 界面对齐

基线：`33f86264d5f5ca6295568a19cab5a0aa692b5bf1`。本轮增加能力，保留已有本地识别、单文件启停、导入、外部启动器目录读取、实例隔离和安装机制。仅本地 Commit，不打包、推送或发版。

## 界面与操作

- 顶部按 PCL2 排列“打开文件夹／从文件安装／下载新 Mod／全选”，刷新改为紧凑图标。实际 Mods 路径放在文件夹按钮提示中，移除重复计数行。
- 多选采用行底色、左侧色条和标题强调。空格、回车可以选择所在行；Ctrl+A 选择当前筛选结果，编辑搜索框时保留其文字全选。Escape 优先取消选择。
- “可更新 (数量)”与“全部”同级。搜索和状态筛选只保留仍然可见的选择；全选不处理隐藏文件。
- 底部操作栏显示数量和更新、启用、禁用、删除、取消选择。更新只作用于所选的可更新文件，启停根据物理状态开放。无法修改的文件仍允许取消选择。
- 使用现有控件与主题资源，适配深色模式。选择增加时淡入 60 ms，位移在 120/270/360 ms 到达 -27/-24/-25；非空选择减少时不重新回弹，清空时 90 ms 退出。减少动态效果、页面退役、快速返回会清除旧时钟；底部留出 95 DIP 避免遮挡列表。
- “下载新 Mod”带入当前实例的精确 Minecraft 和加载器筛选，继续使用现有搜索、详情和指定实例安装。NeoForge 使用完整标识，避免命中 Forge 子串。

## 更新查询

以固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的以下源码为主：

1. `Pages/PageInstance/PageInstanceMod.xaml(.vb)`：筛选、多选、工具栏、下载入口、更新确认和文件名替换。
2. `Pages/PageInstance/MyLocalModItem.xaml(.vb)`：本地行选择、强调和交互。
3. `Modules/Resource/LocalResourceLoaders.vb`、`LocalResourceFile.vb`、`ResourceVersion.vb`：文件识别、双平台更新、加载器匹配与发布时间判断。

七份原始 Git 对象、blob ID、SHA-256 在 `artifacts/mod-management/source/manifest.json`。上游仓库未修改。

本地文件在工作线程中按实际内容生成 SHA-1、MD5 与 CurseForge MurmurHash2（忽略制表符、换行、回车和空格），并重新核对扫描时的长度及 SHA-256。查询每批最多 40 个文件，两平台独立处理：

- Modrinth 先用 `/v2/version_files` 识别，再按当前文件的加载器集合及实例 Minecraft 调用文档化的 `/v2/version_files/update`。
- CurseForge 使用 `/v1/fingerprints/432` 的精确匹配；还要求长度及密码学摘要匹配，不能仅凭指纹接受文件。随后读取项目的兼容文件索引和精确文件信息。
- 候选必须属于同平台、同项目，发布时间更晚、内容不同、匹配实例精确游戏版本，且与原文件加载器集合一致。文件身份不明、不兼容或资料不足时不会猜测更新。
- 两平台结果取兼容的较新项，同时间优先 Modrinth。一方出错保留另一方结果；错误可查看，点击刷新可重试。本地列表不等待在线查询。
- 成功结果按文件路径、SHA-256、原生实例、加载器和来源设置缓存六小时；失败不缓存，手动刷新重查。异步结果同时受请求、页面、实例与原生快照约束。

接口依据：[Modrinth 批量更新查询](https://docs.modrinth.com/api/operations/getlatestversionsfromhashes/)、[CurseForge Core API](https://docs.curseforge.com/rest-api/)。未加入平台搜索、认证或下载源之外的新服务。

## 文件发布与恢复

更新经既有下载器获取，最多并行三个文件，连接数和限速在活动下载间分配；全部下载校验完成后，才进入同步文件事务。复用现有原生目录锁、安装锁、文件句柄及原生实例快照核对，不跨异步等待持有线程互斥锁。

替换前再次核对旧文件摘要、目标别名、重复 Mod ID 与目录状态；下载副本还需符合选中发布的摘要、大小和归档身份。普通文件名跟随平台的新名称；自定义名称参照 PCL2 只裁去共同的前后 `-` 段，再替换唯一的变化部分，保留中文前缀及 `.disabled/.old`。有歧义时保留完整自定义名称。

旧文件移入实际运行目录的 `.pcl-db-mod-backups/<时间与随机标识>/`，与 Mods 同卷且位于其外，避免递归扫描将备份当成活动 Mod。失败或取消会撤销本批已发布文件并恢复原名，只回收本任务持有的副本；外部文件占用恢复路径时不覆盖，保留原文件并报告备份位置。批量启停也会预检并撤销部分更改；“删除”移入可恢复备份，不永久擦除。

确认弹窗关闭后才开始写入；操作复用已有取消、原生实例重读和管理刷新流程。保持三种启动器现有隔离、共享目录和配置，外部设置只读。
