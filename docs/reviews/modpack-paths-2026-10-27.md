# 整合包长文件名、路径与缓存复用

基线：`8209924`。本轮先执行原 Core 全套，末尾结果为 **7,244 项通过**；随后沿名称与路径校验复查，发现旧检查没有覆盖合法长文件名。

## 源码与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModModpack` 和 `ModNet`。上游整合包按资源类型和平台文件名构建下载目标，Modrinth 目标核对所属目录；已有文件按校验规则匹配复制，复制失败再下载，下载临时名称独立生成。固定 Git 原始字节和摘要见 `artifacts/modpack-paths/source/manifest.json`。

确认三处相互关联的问题：

1. CurseForge 文件信息查询，以及 CurseForge／Modrinth 共用的整合包路径校验，调用了限制实例名称最多 100 字符的函数。合法长 Mod 文件名、配置文件名和文件夹因此被拒绝。
2. 整合包的相对路径还被统一限制为 240 字符，多级合法目录及长文件名会在读取包时直接失败。程序原有长路径清单声明不能绕过此处业务限制。
3. 复用文件和恢复已校验缓存时，临时文件名称在目标文件名后追加随机后缀。目标文件名较长时临时名称超限，复制异常走既有回退流程，即使缓存有效仍重新下载；离线时也无法利用该副本。

使用最终 36 项夹具、仅保留原生产实现构建，**18 项失败**。错误包括“实例名称无效”“整合包路径无效”及长文件名无法零网络复用，见 `artifacts/modpack-paths/baseline-final-fixture.log`。单改路径校验后，四条安装重试／缓存复用检查仍失败；这一步的较早夹具保留在 `path-only.log`，用于确认临时名称问题独立存在。

## 修改

- 实例名称仍使用原 100 字符限制和原错误信息。新增内部普通路径段入口，长度限制为 255 字符，共用原非法字符、空名称、首尾空白、尾点及保留名检查。
- 普通文件名和归档路径改用路径段入口。相对路径校验上限改为 32,767 字符；逐段限制、根目录／反斜杠／冒号／父目录检查及后续 `SafeFiles.UnderRoot` 保持。最终路径还必须通过本地 IO 的实际校验，不宣称所有机器或文件系统都支持上界长度。
- 复用和缓存恢复的副本使用目标目录内的 `.pcldb.reuse-随机值.tmp`、`.pcldb.cache-随机值.tmp`，不增长原文件名。保留摘要检查、同卷提交、取消检查、失败回退与清理；已有清理检查的通配符仍能发现这两种临时文件。

不改动 UI／动画、来源选择、加载器匹配、版本隔离或外部启动器配置。

## 验证

新增 `ModpackPathChecks` 36 项，注册到 Core 默认全套及 `--regression modpack-paths`：

- 两种格式各三条合法覆盖路径：长路径段、多级相对路径超过 240 字符、255 字符文件名。
- 两种格式各六条非法路径：父目录、保留名、256 字符路径段、尾点、冒号及超过 32,767 字符的相对路径。
- Modrinth 文件清单中的 150／255 字符文件名；CurseForge JAR、资源包 ZIP、光影 ZIP 对应长度的元数据查询与类型绑定；非法平台文件名继续拒绝。
- 实例名称 100 字符仍通过，101 字符仍拒绝。
- 两平台使用真实回环下载和文件写入，安装 255 字符 Mod 文件名及多级配置路径；发布前取消、不发布半成品，新请求从已校验缓存重试，核对文件字节、实例隔离、包内其他设置及共享 Mods／全局设置保持。已有目标在网络请求前拒绝。
