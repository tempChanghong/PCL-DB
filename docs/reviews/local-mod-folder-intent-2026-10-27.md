# 本地 Mod“打开文件夹”的请求与实例归属

基线：`7e80e91`。沿管理页的入口检查，继续审查本地 Mod 目录读取与刷新、文件操作、返回及改选实例的交接。本轮只改目录动作入口；原生隔离、共享路径、文件安装及动画实现保持。

## 源码依据与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `PageInstanceMod`、`ModLoader`、`FormMain`。PCL 打开当前实例 `PathIndie/mods`，显式重载 Mod 列表；加载器先改变状态再通知取消。桥接程序需要异步重读外部原生配置，因此另外维护实例和请求归属。三份原始 Git blob 与 SHA-256 见 `artifacts/local-mod-folder-intent/source/manifest.json`。

原入口先清空并取消旧请求，通知结束后才绑定实例和分配新请求。受控取消回调中实际启动新目录、列表刷新、文件操作或返回并打开另一实例的 Mod 页，可复现：

- 新目录读取已开始，旧外层点击再次调用目录读取，覆盖较新请求。
- 列表刷新或文件操作已开始，旧目录点击仍执行读取，其错误覆盖“正在读取 Mod 列表”或“正在导入”的当前提示。
- 已返回并打开另一实例的 Mod 页，旧点击重新取得新实例并读取，将错误写到新页面。

## 修复

在取消通知之前捕获原实例和读取代次，分配并登记本次请求。通知返回后，核对请求、实例、代次、页面及当前读写／输入门控。新动作可以替换或退役本次请求，过期点击直接退出，不再发起目录读取或改写提示。

旧请求取消也放入原有异常处理与清理范围。本次动作最终只清理自己的请求；替换、刷新、文件操作与返回产生的新请求由其原流程处理。未增加设置、主题或动画参数，未改目录解析和文件事务。
