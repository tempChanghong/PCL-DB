基线：`f81e42a`。继续检查本地 Mod 读写和返回交接，发现通用文件操作入口在取消旧读取之后才捕获实例并设置写入状态，导致原目标及互斥边界晚于取消通知。

## 源码依据与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `PageInstanceMod`、`LocalResourceLoaders`、`ModLoader`：导入固定实例，更新复制清单和实际 Mods 路径，同目录读取等待更新结束；加载器先改变状态再通知取消。桥接程序补充异步请求和页面归属，原始 Git blob 与 SHA-256 见 `artifacts/mod-write-start/source/manifest.json`。

受控旧目录请求的取消通知中，实际执行返回、改选和打开另一实例，随后让原导入继续。12 组临时目录真实导入中，原实现将本应导入 Fabric 实例的 `arriving.jar` 写入了后来所选的“我的原版”，并用该操作结果改写新页面。现有文件与原生配置字节未被改写，但新增文件位置错误。

另复现两类启动问题：取消通知中完成同目录刷新后可重入第二次写入，两个委托及代次覆盖；启动通知中请求取消时，写入请求尚未登记，取消无效，文件操作仍被调用。

## 修复

通过既有可写检查后，先绑定原实例、写入请求、操作代次和写入标志，再取消旧读取。新导航可以继续查看其他目录，但原操作只使用起初授权的目标；同目录读取沿用原等待机制，重复文件操作被既有写入门控拒绝。

取消旧读取放进原异常处理和清理范围，文件委托执行前检查取消令牌。操作提示只写入仍属于原实例的本地页面；其他目录保留自己的列表和反馈，共享目录继续使用已有影响提示及完成刷新。

Core 的目录校验、文件冲突、原子发布、备份与原生隔离解析未改；页面和确认动画时序保持。
