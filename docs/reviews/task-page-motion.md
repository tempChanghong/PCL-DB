# 安装与任务页之间的动画修复

基线为主题跟随提交 `629f9a4`，在其上本地修改、验证并 Commit；不打包、推送或发版。

## 复现与源码依据

已检查用户提供的 24.77 秒 / 30 fps 录屏及当前代码。`SetDownloadView` 原来只有进入/离开整合包时调用 `PclSurfaceMotion`；原版安装/浏览与任务页之间直接执行 `ApplyDownloadView`，后者停止水平选择页动画并切换可见性。因此下载按钮进入任务、任务返回安装选项均没有通用页面动画。

新增真实安装处理函数回归，在业务源码修改前得到预期失败：已有 359 项通过，随后缺少任务入场时钟的断言失败，回执为 `artifacts/task-progress-motion/before-motion.json`。不是用静态截图推断动画存在与否。

读取固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `FormMain.xaml.vb`、`Controls/MyPageRight.vb`、`ModDownload.vb`、`PageDownloadInstall.xaml.vb` Git 对象。`FormMain` 将任务管理同样交给 `PageChangeAnim`；其右侧页面退出后 110 ms 交接，再延后 30 ms 入场。`MyPageRight` 按控件逐个退出（70 ms 淡出和 -6 DIP，间隔 15 ms）、逐个入场（-16 DIP，并行 250 ms Fluent 和 350 ms Back，间隔 25 ms），滚动条独立进入。规范化副本与 SHA-256 在同目录 `source/`、`source.json`。

## 修改

将所有进入/离开任务页的跳转接入现有右侧页面动画，包括原版点击下载、查看已有任务、卡片返回、标题返回和 Escape 所共用的路由。原版版本列表与组件选择页之间仍由原水平切换所有者负责；整合包原有流程继续使用通用右侧切换。

在变更可见性、侧栏/工具栏宽度或释放水平卡片动画前，先冻结当前显示帧；快速反向时使用一个合成帧，避免截图来自已经复位的页面。退出层不接受输入，正文在交接阶段门控，入场回弹期间恢复交互。进度与完成状态更新不重播页面动画，安装及取消不等待呈现完成。返回不创建新任务，也不重建已有组件正文、名称和滚动位置。浮动下载按钮继续使用现有显示/隐藏规则，不额外启动竞争动画。

继续使用控制器已有的过期时钟判定、设置页交接、尺寸变化/隐藏/卸载清理和关闭动画分支，没有增加逐帧布局计时器或新的截图实现。

## 验证范围

新增 31 项动画检查，实际调用安装、完成、取消和返回处理入口，安装器由可控任务替代，不下载或发布真实实例。覆盖：

- 下载后逐卡片入场、交接延迟与隐藏输入门控；同一按钮重复激活只启动一次任务。
- 在入场动画中完成安装，结果与操作按钮继续显示；过期进度不能回退已完成状态。
- 返回时组件对象、卡片正文、名称、滚动位置不变；入场卡片按 25 ms 错峰。
- 返回尚未结束时重试，退出图逐像素匹配当时显示帧；旧时钟不能覆盖新页面或解除新门控。
- 重试取消、旧任务回调、标题返回、设置交接、已有任务重开、调整尺寸、真实未暂停 Dispatcher 播放、静态分支及卸载。

原有静态导航预览继续要求立即呈现终态、恢复输入且不创建时钟。动态的原版卡片检查改为要求通用右侧页面接管和交接期门控，继续检查旧水平/卡片时钟清理与业务状态保留。两种模式分开断言，不能用静态预览没有时钟推断真实运行缺失动画。
