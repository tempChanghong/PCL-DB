# 前置资源查询：取消旧请求时的点击交接

基线：`639e892`。继续检查下载／搜索详情的快速点击、标题返回、取消重试及动画联动，发现 `OpenResourceDependency` 先通知旧查询取消，之后才登记本次请求，留下启动交接窗口。

## 依据和复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `MyResourceItem.MyResourceItem_Click`、`PageDownloadCompDetail` 和 `ModLoader.State`。前置项目通过页面切换进入详情，并传递当前实例／加载器上下文；前置列表复用项目缓存；加载器先改变状态，再通知取消。三份原始 Git blob 与 SHA-256 保存于 `artifacts/dependency-handoff/source/manifest.json`。

PCL-DB 的前置按钮还需异步解析项目／固定版本。因此在旧请求的确定性取消回调中，实际调用现有点击和标题返回入口，复现两条路径：

- 先查询 A，点击 B 取消 A 时又有了更晚的 C 点击。旧 B 入口恢复后覆盖 C 的请求，最终进入 B 详情。
- 点击 B 取消 A 时已通过标题返回搜索。旧 B 入口仍在返回后登记请求并发出 HTTP 查询，返回操作无法取消这一后来登记的旧意图。

## 修复

捕获旧请求并先登记本次查询，在 `Try` 内通知旧请求取消；通知返回后，先复核本次令牌、请求身份、原项目及原链接的页面／交互状态。更晚点击或标题返回已接管时，旧入口直接退出，不创建客户端或发出查询。

取消通知也纳入现有异常处理和请求清理。结果接收、链接反馈、唯一返回帧捕获、混合类型解析、筛选／滚动恢复、页面动画及下载安装实现保持原有逻辑。

## 验证

Mod／光影页 × 明暗 × 开关动画 × 两条路径，共 16 组、48 项。使用同一最终夹具，旧实现 24 项失败，修复后专项全部通过。真实离屏 WPF 控件和 HTTP 客户端配合受控处理器，旧响应故意晚于取消返回；检查真实查询次数、最新请求、详情归属、返回栈、父发布版本对象恢复、动画门控恢复及安装任务代次不变。不访问远端服务，不写入游戏或外部配置。

接入 all、motion、pack-search。策略 `PCL-DB-checks/2026-10-27.10`：all 3,054、motion 2,524、pack-search 1,529，组间有重叠、不累加；navigation 保留 1,852。运行入口沿用统一限时 all／motion 600 秒、pack-search 180 秒。构建、固定 PCL 来源／资源、44 项限时策略、97 项验证契约、19 项进程检查另验。最终以 `artifacts/dependency-handoff/validation.json` 及各组回执为准。
