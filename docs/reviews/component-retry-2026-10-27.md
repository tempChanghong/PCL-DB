# 组件重试：先登记请求，再取消旧读取

基线：`3562e0e1a29d5f3abb51c71ad0ab2bd78a4d9ea9`。检查原版安装页组件刷新时发现，`RefreshComponentListsAsync` 取消旧请求后才登记新请求，启动阶段又从共享字典取请求，存在跨重试和原版版本的交接问题。

## PCL2 源码依据

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `PageDownloadInstall` 与 `ModLoader`。上游进入组件页时为所选原版创建 Forge 加载器、按组件加载状态刷新摘要和展开权限；`ReloadSelected` 显式防止状态事件重入。加载器先更新状态，再通知取消。

两份原始 Git blob 与 SHA-256 记录于 `artifacts/component-retry/source/manifest.json`。本工具的取消令牌及代次检查属于桥接实现，不声称与上游内部结构相同。

## 复现与修复

通过旧 Fabric 请求的受控取消通知，调用实际组件刷新或 `SelectVersion` 入口，复现三条路径：

- 更晚的 Fabric 重试已完成，旧外层入口恢复后又登记并发出查询，造成重复读取。
- 已改选另一个原版并完成新组件清单，旧入口仍以旧原版发出读取、移除新清单，留下不能结束的待加载状态。
- 取消通知抛出异常，发生在加载器的异常处理区之外，刷新任务直接失败，未正常提供失败和重试反馈。

修复先为本批组件登记新请求和待加载状态，并保存新旧请求的本批快照。逐项加载器在 `Try` 内取消捕获的旧对象，返回后复核组件、原版引用、代次及请求身份，再创建查询。启动阶段不再从可能被重入更新的共享字典借用请求。未启动查询的过期请求也经过其自身的 `Finally` 清理；异常继续进入原获取失败及重试展示。

保留 100 秒组件读取限时、已有选择与自定义名称、已明确取消的依赖，以及不同组件的并行查询。未改安装发布、兼容规则、外部启动器配置或卡片折叠动画参数。本轮聚焦单项重试，不声称完成对全部取消入口的穷尽证明。
