# Mod 文件操作完成后的原生目录重读

日期：2026-10-26。基线 `5102039da8b10664fe54476dbaeea74df3371a09`。Beta 5.0 后续本地源码，暂不发行。

## 源码依据与问题

主参照固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8`：`PageInstanceMod.LoaderRun` 使用当前实例 `PathIndie` 下的 Mods 目录，`ReloadModList` 在文件操作后重新加载；`LocalResourceLoaders` 协调目录更新与取消；`MyPageRight` 区分加载、重试和页面退出。原始 Git 对象分别为 `b5e2422419d03f05be7d0c060694d2606c9763ff`、`a36c7154d12c9f10e86b4f2c9630fa66b73e1fba`、`d9831cb03d9a14754e7e8ec0673f97ff02588652`，字节及 SHA-256 在 `artifacts/mod-write-refresh/source/manifest.json`。

上一轮处理了管理刷新已经发现配置变化时的交接。但如果外部启动器在 Mod 操作期间改变隔离设置，管理页面没有刷新，当前两个内存快照仍指向同一路径。操作完成会进入“上下文相同”分支，只扫描旧目录，不重读原生配置。这样界面仍显示旧列表，立即重试也拿着旧配置快照，被写入内核的变更校验拒绝。

这不是已经证实的越界写入。现有写入内核继续核对冻结配置和目标，问题在于完成后的界面与下一次操作没有采用新配置。

## 修改

- 文件操作完成时，即使内存中的实例上下文看似相同，也先重读所选原生实例，再扫描实际运行目录。沿用既有读代次、取消令牌、目录写入检查和界面动画。
- 重读失败或实际运行目录变化时，保留带原实例名称的文件操作结果，避免后续列表读取错误使用户不知道前一个操作成功还是取消。当前列表自己的读取错误继续保留。
- 返回、切到设置或改选实例后，旧重读结果不能替换新页面、旧焦点不能跟随回来；新任务和新操作的反馈仍受原有归属检查保护。

原生配置只读；没有改变 PCL、HMCL、PCL-CE 的隔离规则、写入内核、下载来源或动画曲线。

## 验证及边界

新增 42 项：三种绑定 × 静态浅色/动态深色，共六组，每组七项。检查未被管理刷新观察到的独立转共享、实际扫描目标、立即真实幂等导入、配置损坏时读取失败与操作结果并存、同页修复回独立目录、返回/设置/另一个实例对迟到原生读取的撤销，以及所有归档和预期配置字节保留。

独立 Git 基线仅附加同一专项文件，12 项通过、30 项失败观察；修复后 42 项通过。30 项是缺陷在多场景中的重复观察，不是 30 个独立 Bug。

首次导航回归停在既有“取消回调内同步完成”夹具；动画回归也停在其同步等待文件操作的步骤。新增原生读取使用默认后台工作线程，而公共本地 Mod 夹具原先只为目录枚举和写入提供同步实现，因此不再满足这些同步完成的前提。现将同步的实际原生解析一并放入公共样本准备函数，保留原有全部完成状态、反馈、动画和焦点断言；异步原生读取及返回撤销仍由新增专项覆盖。首次记录保存在 `artifacts/mod-write-refresh/first-navigation-attempt/` 与 `first-motion-attempt/`，夹具适配不计为额外产品缺陷。

实例读取、三种原生配置解析、Mod 识别与幂等导入均使用实际代码。写入完成时序和迟到读取使用受控任务，没有模拟真实并发落盘；真实导入只对已有相同归档进行校验和跳过。配置只由夹具在独立目录中修改。未接触用户实例或外部设置，未干预 Visual Studio 调试，未作人工键盘/帧率及实际游戏验收。
