# 补全、刷新与新目录动作的入口归属

基线：`7d8a1cb`。沿管理页上轮取消交接检查，继续审查“校验与补全”和刷新入口，补齐管理代次之外的目录动作代次，以及补全入口的原实例绑定。

## 源码依据与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `PageInstanceOverall.BtnManageCheck_Click`、`ModLoader.State` 和 `FormMain`。PCL 补全操作针对所选实例，检查修改锁与重复任务；加载器先改变状态，再通知取消。本工具已有原生配置重读及原版补全准备流程，异步入口需另外保存实例与操作代次。三份原始 Git blob、SHA-256 见 `artifacts/management-intent/source/manifest.json`。

受控取消通知中实际调用已有选择／目录按钮，复现三种情况：

- 补全点击先取消旧目录读取，通知中已改选 Fabric 实例；旧入口却在取消返回后才取得实例，继续读取新实例，并将新详情的“不支持补全”说明改成旧操作错误。
- 补全点击取消旧目录读取，通知中已明确打开新的目录；旧入口继续开始补全准备，抢占父请求和加载状态，并留下与新目录动作无关的错误。
- 刷新入口只比较管理代次。新目录动作使用自己的代次，因此旧刷新仍继续扫描，并留下扫描错误，未尊重更晚的目录操作。

## 修复

补全入口在通知取消前绑定原实例，保存预期管理和目录代次。通知返回后复核实例、目标绑定、页面、代次及原有忙碌／输入门控；已有新操作时直接退出，不分配补全请求、不读取新实例，也不写反馈。

刷新入口同时核对目录代次。新的扫描或目录动作都能使旧外层刷新失效，保留原有正常刷新和迟到结果检查。

目录解析、原生隔离配置、共享目录、文件校验／安装、原补全安装页和动画时序均未修改。
