基线：`fa197ddcc1502058fe2789545e658fa912e4da7f`。

## PCL2 依据

重新读取固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的四份 Git 原始文件，摘要见 `artifacts/resource-retirement/source/manifest.json`。

- `PageDownloadLeft.PageGet/PageChange/PageChangeRun` 保留各下载子页的实例，统一切换与异常处理，停止冲突动画后进入目标页。
- `PageResource.StartNewSearch/LoaderInput` 将结果容器与已接受查询绑定，等价输入保留结果，分页、版本和加载器属于相应资源页。
- `ModLoader.LoaderTask.IsCanceledWithThread/Start/Cancel` 让旧工作先失去状态与输出归属，再处理取消通知。
- `MyPageRight.PageOnForceExit` 使用 AniStop 清理被替换的动画，不将强制退出当作正常入场完成；PageOnEnter 保留原有加载与内容过渡。

PCL-DB 继续使用自己的共享资源页面、异步请求和取消令牌，按上述原则保护分类缓存、实例筛选、结果和动画归属。

## 已复现的问题

原 `CancelResourceRequests` 一边发送取消通知，一边读取共享请求字段。通知可同步启动新搜索或详情，旧流程随后会取消、释放或清空这些新字段，并重置新加载状态与动画；首个通知报错还会跳过其他旧请求。

原分类切换在动画的内容更新回调中执行上述取消，回调接受新操作后，旧分类仍可能继续写入缓存、表单和页面，控制器也会继续创建较早的分类时钟。管理页“下载新 Mod”的筛选设置和随后 ShowDownload 同样可能覆盖较新的查询、分类或设置页。

初始夹具共 50 个场景、150 项检查，旧实现 **91 项失败**，记录在 `artifacts/resource-retirement/baseline-Retirement/`。首轮修复通过后，最终夹具在保持 150 个断言入口的基础上，额外检查旧卡片入场被清理时不误发完成回调。

## 修复

- 先捕获六类旧读取并解绑全部共享字段：前置、名称、搜索、详情、搜索图片、详情图片。名称缓存、加载控制器和旧卡片动画同步退役；后续操作只能访问新的归属。
- 返回的取消动作只引用捕获的旧源，重复执行不会重复通知。即使某个通知失败，也继续通知其余旧源；只释放相应旧名称与图片源，读取器自己的请求仍由其结束路径释放。
- 分类更新期间暂存取消通知，先完成目标分类、缓存、实例筛选和入场动画绑定，再执行旧通知。嵌套分类准备继承暂存队列，作用域在 Finally 中恢复。
- 分类和读取上下文已被较新操作替换时，旧流程不再补写提示或自动搜索。仍属于当前页面的通知异常使用现有提示反馈，任务入口仍能收到异常并沿原任务结果流程处理。
- 管理页发起新 Mod 下载后，检查分类代次、主页面、实例身份和当前隔离上下文，避免较早的 ShowDownload 抢回新页面或错误实例。
- 新增内部动画 Cancel，只移除旧时钟并还原属性；正常 Finish 仍保留完成通知。分类先捕获当前可见画面，继续沿用原卡片过渡时序与样式。

没有修改下载内核、源策略、安装计划、文件校验、隔离设置或外部配置格式。
