# 详情完成期间切换项目的交接修复

基线：`f0a011d35bb20ae1eba1c31fe9cc0b5492fdb6c9`。本轮只修复 App 的详情完成提交边界，Core、界面结构、动画曲线及配置格式保持。

## 问题与依据

`LoadPackDetailsAsync` 在等待项目与版本信息后核验请求，但更新头部会退休旧图片请求。该请求的同步取消通知可以打开新项目。头部渲染自身已有代次检查，会保留新头部；调用者却仍隐藏错误提示并执行 `InitializePackVersions`，覆盖新项目刚建立的加载卡片、筛选或重试状态。

固定 PCL2 `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的详情加载在取消后停止发布，loader 在执行委托后重新检查当前运行，MyPageRight 保持 UI 完成通知顺序。其离页后台完成逻辑也说明不能以页面可见性禁止有效请求填充缓存。CE `915ac29795efbdf6373417389e181e1504117048` 的对应 C# 代码仅作取消和完成顺序参考，未移入上游线程终止实现。

原始 Git 字节及固定文件摘要保存在 `artifacts/detail-completion-ownership/source/manifest.json`；时序复核在同目录 `initial-review.md`。

## 改动

- 成功提交回调入口重新检查原始项目对象、该次 CTS、取消和关闭状态。
- `RenderPackProject` 返回后再次检查，旧流程失去归属立即退出。
- 失败提交回调入口采用同一门控，避免动画收尾通知期间切换后的旧错误回写。

原完成标记门控、只清理自己请求的 Finally、令牌释放和隐藏缓存行为保持。没有新增 await、锁、状态字段或公开接口；不改安装目标、共享目录和隔离设置。
