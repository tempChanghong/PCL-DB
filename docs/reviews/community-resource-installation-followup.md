# 指定实例安装后续检查与修复

基线 `88d33e058728e7ebf4d849bcebcd1b55e257a8e5`。围绕资源安装、三启动器隔离、共享目录、数据包存档和本地管理刷新检查。保留版本、配置格式、另存为入口及第一批下载机制；仅本地 Commit，暂不推送、打包发版。

## 复现与修复

1. **目标冲突被误报成缓存损坏。** 目标已有同名不同内容文件时，旧安装流程先获取缓存，再用“下载缓存已改变”提示校验目标失败，容易让用户反复重新下载。新增回环复现先失败，修复后提示目标被占用、已有内容保留；文件、目录占位和禁用 Mod 别名在网络获取前拦截。
2. **已安装的正确文件仍依赖下载缓存或网络。** PCL `ModNet.CheckExistingFile` 优先校验目标；这里原本要先获取文件才能跳过发布。现在在工作线程的原生目录互斥内校验完整长度与已声明摘要，匹配就直接完成；Mod 仍检查归档是否有效。全部三启动器/隔离目录与四类资源矩阵中，冷缓存复用共 40 种组合、零 HTTP 请求。辅助安装锁仍可能创建，不声称目标读取过程完全零写入；外部配置不写入。
3. **最小窗口的长弹窗溢出。** 长发布名称、路径和读取错误同时出现时，470 DIP 高表面上的确认按钮底边实测达到约 542.7 DIP。按固定 PCL `MyMsgSelect` 的星号正文行、滚动内容、固定底部按钮结构调整后，底边为 404 DIP。保留 508 DIP 宽度、原字体/提示/选择框/阴影、40 DIP/-4° 入场及退场；重开弹窗取消旧滚动并回到顶部。现有整合包命名与可选文件确认共用这一修复。

预检不能替代最终发布：检查后下载过程中仍可能出现新文件、目录或配置变化，正式发布继续持有原生目录链和文件句柄，重新核对目标/存档，失败只清理自己持有的新文件。已有同名不同内容不自动替换；也不自动删除或启用禁用 Mod。原生 Mutex 的获取与释放都在同一工作线程，不跨 Await 持锁。

## 源码与关系检查

- PCL 固定 `5ef81e490ae46b1100d61e33d0183094c7a80ca8`：重读 `PageDownloadCompDetail` 的 `PathIndie`、Mod/数据包适用性和资源目录；`ModNet.CheckExistingFile` 的目标长度/摘要检查；`MyMsgSelect` 的正文与按钮布局及动画。沿用原资源目录映射和保守相容性，没有扩大快照推断或加入自动前置安装。
- HMCL 固定 `0d20910ea302a907d6a01fec9244ab10d2993d5e`、PCL-CE 固定 `915ac29795efbdf6373417389e181e1504117048`：保持已存在的只读原生目录解释。PCL-CE 只作辅助，页面结构仍依 PCL2。十一份原字节源码与 Git blob/SHA-256 保存在本轮 source 清单中。
- 数据包必须显式选择已有存档；切换实例取消旧读取、清空旧选择。新增真实回环获取期间修改 `level.dat` 的检查：旧计划不发布，更新后的存档保留；重选后复用已验证缓存成功安装。只检查存档目录身份与 marker，不解析/写入 NBT。
- 本地管理保持“失效后重新读取”的机制，新增晚回包检查：同一个共享运行目录失效后，之前未取消成功的读取不能恢复旧的成功状态或覆盖列表；随后真实重扫能恢复新 Mod，外部设置字节保持。未新增本地资源包/光影包启停页。
- 原子发布、禁用别名、已知重复 Mod ID、同物理目录互斥、配置/目录替换、取消和重试仍在原专项内覆盖。普通资源互斥提示改为资源目录用语；保留原 Mods 互斥名称与键，避免影响现有本地 Mod 管理。
