# 安装索引与补全客户端复验取消

基线 d78cc2fa6592e9da1704fa6feef1fd2094f25420。继续安装校验的取消收尾，保留 VB WPF、VB 测试、net48、程序集／接口／配置／资源身份，不打包发版。

## 问题与修复

MinecraftInstaller 仍有两次文件散列不接取消：旧补充实例继续使用原 assetIndex.id 时的共享索引保护，以及已有实例补全中、替换客户端前的最终复验。原显式取消检查在摘要之后，因而用户取消时仍会先读完整份目标文件。

本轮只给两处 Matches 传原 token，复用既有分块散列，无新接口、令牌源或生产测试钩子。SourcePolicy 对内存 metadata 的 ComputeHash 不属于本轮，不把所有元数据工作都称为已经可取消。

## 阶段、配置与原子提交

- 共享索引初检只针对保留旧索引命名的补充实例修复，在后续 index 请求、payload 和暂存树之前。原冲突继续拒绝覆盖共享索引，普通／新补充实例的 pcldb-SHA1 私有索引命名不变。
- 最终客户端复验位于资源 Publish 之后、JSON 读锁及隔离 guard 之内。取消必须释放文件／配置／根锁，保留原客户端和 JSON／INI；不能因取消而撤回已经原子修复完成的资源。
- 保留 needsReplacement、后续显式 token 检查、guard.Verify 和 CommitFile 次序。取消不把损坏的旧客户端替换为未确认结果；同名新令牌重试继续复用已校验的完整内容。
- Complete、已成功安装后的 ReleasePublishedClient 和必要回滚不接取消。并发取消与摘要不匹配沿既有 Matches(token) 的语义，不声称所有错误优先级都相同。
- 配置读取、路径冲突、三启动器／隔离判定与现有实例的元数据接受范围不变，没有写入用户配置的新增路径。

## 验证与限制

专项沿实际 InstallAsync 构造较大的有效共享索引，以及与正确客户端同长度、内容不同的已有客户端，确保真正进入摘要计算。以生产 InstallCoreAsync 的直接调用者和提交阶段／文件读租约区分目标，排除 SourcePolicy、下载器、缓存与资源发布散列，不靠第 N 次摘要猜测。

检查索引保护在后续请求／暂存前取消，和客户端最终取消时 JSON／INI 可读但禁止外部写入；验证原字节／时间戳／配置、完整资源修复保留、锁释放及新令牌重试。新增必要 None 控制，保留既有索引冲突、私有命名、元数据变化与晚取消套件。完整缓存的 payload 网络字节与 metadata 请求分开记录，不把零 payload 字节称为零请求。

新增 21 项：旧补充索引 8、最终客户端 10、探针恢复 3；原 8263 项保留，全量增至 8284。同一新宿主配锁定旧 DLL 为 19/21，两项预期早停失败：索引读满 524342 字节、客户端读满 524307 字节，均为 129 块。候选 21/21，两目标均在首块 65536 字节停止；None 控制仍完整读取各自文件。
