## PCL2 依据

重新读取固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的三份 Git 原始文件，摘要保存在 `artifacts/search-submission/source/manifest.json`。

- `PageResource.xaml.vb`：`StartNewSearch` 重置页码，仅在 `Loader.ShouldStart` 接受新输入时更换 `Storage`，避免重复搜索丢失结果容器。
- `ModLoader.vb`：`LoaderTask` 以输入、状态及当前线程判断请求是否过期；取消或被替换线程的结果不再发布，异常进入失败状态。
- `MyPageRight.vb`：加载状态驱动页面过渡，并保留失败后的点击重试入口。

PCL 使用线程加载器，PCL-DB 使用异步任务和取消令牌。本次沿用相同的结果归属与失败反馈原则，为本工具补齐同步取消通知的交接保护，不照搬线程中断实现。

## 已复现的问题

分页读取已先绑定新请求再通知旧工作，但提交新搜索仍先取消共享字段里的旧请求，之后才设置新会话。取消通知若同步触发更晚的查询，较早的操作会继续覆盖新会话，甚至取消新请求并发送过期查询。取消通知异常也可能逃离事件处理，绕过页面重试提示。

初始 32 个场景、96 项检查，在旧应用代码中复现 **80 项失败**。首轮修复后又补充旧详情／前置请求在通知期间正常完成并释放的 16 个场景，复现 **48 项失败**：向已释放的取消源再次发出取消，会误报当前搜索失败。

早期复现宿主意外进入正常应用启动，异常提示导致运行停滞；这些运行不计为有效验证。隔离宿主在构造测试 Application 时取消其排队的正常启动操作，只运行真实 WPF 夹具，再取得上述可对照结果。保留停滞记录、宿主修正记录及失败回执，不将其算作通过。

## 修复

提交搜索先发布新会话、查询键和结果上下文；分页读取器再同时绑定搜索及图片请求，随后只通知捕获的旧搜索、图片、详情和前置请求。取消结束后重新检查归属，较早操作不能改变较新搜索的页面、加载提示和结果。

所有旧取消通知进入现有读取异常边界，当前请求失败时显示原有重试提示，旧请求异常不污染已经接受的新查询。已正常完成并释放的旧上下文仅忽略其 `ObjectDisposedException`；注册回调抛出的异常仍作为失败处理。旧请求只清理自己的请求、加载展示与图片所有权。

重复查询保留、搜索缓存、已有返回帧规则、400 ms 加载等待／最小停留、卡片过渡与输入门控沿用现有实现。未新增平台访问方式或改变文件安装机制。
