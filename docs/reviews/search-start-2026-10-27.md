# 搜索分页：同时绑定搜索与图片请求后再取消旧工作

基线：`a3d3b4f`。沿搜索刷新、分页及返回继续检查，发现 `LoadPackSearchPageAsync` 先通知旧请求取消，再从共享字段取消／释放图片请求，最后才登记本次读取和加载展示，存在跨请求交接问题。

## 源码与复现

重读固定 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `ModLoader.State`、`ResourceSearcher.SearchResult/GetLoader`、`PageResource.StartNewSearch` 和 `MyPageRight`。上游先变更加载状态再通知取消，按来源保存游标和搜索结果，设置 60 秒重载间隔；搜索入口明确防止连续搜索导致存储引用丢失。四份原始 Git blob 与 SHA-256 保存于 `artifacts/search-start/source/manifest.json`。

在真实旧搜索／图片令牌的受控取消回调中调用现有分页或提交搜索入口，复现三条路径：

- 旧读取取消时已发起更晚的同会话第一页读取。旧翻页入口恢复后覆盖新请求、取消新图片令牌，并发出不再需要的下一页查询，给最新第一页附加过期来源错误。
- 图片取消时已提交新查询。旧入口恢复后释放新图片来源并替换搜索／加载归属，新查询虽有结果却无法正常展示。
- 取消通知抛出异常，发生在原异常处理区之外，任务直接失败，没有终态错误展示和正常重试反馈。

## 修复

先捕获旧搜索／图片对象，同时登记本次搜索和图片来源；在 `Try` 内取消捕获的旧搜索，并用嵌套 `Finally` 保证旧图片的取消／释放也只作用于捕获对象。更晚的分页或新查询可以接管当前来源，旧入口不再通过共享字段清理新对象。

取消返回后先复核会话和请求，仍有效时才更新翻页按钮、启动加载展示；展示返回后再复核，才创建查询客户端。通知异常进入现有错误反馈与请求清理。保留会话游标、缓存、混合来源预览、页尾边界、后续页错误保留已有结果、图片独立加载及动画参数；未改动实例、隔离、原生配置或安装器。
