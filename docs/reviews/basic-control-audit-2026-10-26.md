# 普通按钮与版本列表行的交接检查

日期：2026-10-26。产品基线：`49299e9af1a5e6669f3c8b2488645e4a194b298c`。继续主动检查 PCL 风格、快速切换、取消及动画状态，本轮修复限定在普通按钮和版本列表行。

## 源码与现象

以 PCL `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 `Controls/MyButton.xaml/.vb` 和 `MyListItem.xaml/.vb` 为主参照，读取固定快照中鼠标按下/释放/离开、AniControlEnabled、配色和选中动画分支。保留原始 XAML、几何、字体、按压缩放、并行动画曲线和时长。本轮未引入 PCL-CE 的样式或新功能。

在旧产品源码附加同一专项检查、使用隐藏 WPF 表面复现：

- 普通按钮与列表行按住后失去键盘焦点、丢失鼠标捕获、完整主题切换，再释放，仍触发旧点击。明暗模式各自复现。
- 列表行在父级门控关闭时接收按压，门控恢复后释放会触发点击。实际鼠标通常会被 WPF 门控拦截，但迟到事件、程序调用不应把被拒绝的输入带到新页面。
- 两类控件遗漏既有 `PclControlMotionPolicy`：普通按钮的缩放没有系统减少动画判断，列表悬停/选择也只检查加载和可见性。该项由调用链确认；不会把“缺少测试策略接口”的基线失败冒充已切换真实 Windows 动画设置的验证。

## 修改及冲突处理

1. 在失焦、捕获丢失和完整外观切换时退役待完成手势。门控、隐藏、禁用和卸载统一走现有策略清理；新事件和释放同时校验可用性、输入门控及加载后的可见性。
2. 普通按钮缩放和颜色、列表行悬停与选中动画使用现有减少动画策略。运行时关闭动画立即清理旧时钟；新点击及选中仍同步生效。重新开启动画恢复 PCL 曲线，不修改系统偏好。
3. 区分“仍按住”和“已经释放”：普通失焦不打断已释放的按钮回弹或列表悬停时钟。动态主题的颜色帧继续保持手势和几何时钟；完整外观切换才退役旧手势。
4. 保留未托管控件的现有调用约定，便于原有页面构建与检查；加载到实际页面后，隐藏或被门控的控件不接受新输入。没有增加鼠标捕获，保留正常的按压、离开取消和单次点击行为。

没有修改下载来源、安装目标、共享目录互斥、隔离配置、整合包或原子发布实现。设置保存与本地管理动作仍走原路径。
