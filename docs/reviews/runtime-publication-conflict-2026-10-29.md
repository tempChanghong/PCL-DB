# 共享组件运行库与实例发布的冲突修复

基线：`9909a213278fc935facc8999aa87a65618570fcc`。本批继续第二轮逻辑收尾，不改变 VB 界面、net48、配置格式或程序集身份，不打包发版。

## 实际缺口

组件 Apply 阶段已检查并发布运行库，但该阶段结束就释放短期读租约。MinecraftInstaller 随后仍要等待资源等并行分支，最终才发布实例。ComponentRuntimePublication 原来只把无上游摘要的文件加入 FrozenFiles；已有 SHA／MD5／S3 摘要的文件未进入最终保护列表。

真实安装夹具在“组件安装完成”和最终 commit 两个边界修改支持库，覆盖首次发布／复用已有文件与同尺寸改写／删除／换成目录。旧 Core 的 12 个组合均成功发布实例，即使版本 JSON 引用的共享文件已经错误或缺失；不是仅在私有方法上推测结果。另有四种摘要各两条发布路径的 8 个检查确认旧列表为空。

## 修复与所有权

仅修改 ComponentRuntimePublication：

1. 每个输入先复制为自有的目标与完整性声明，再进行同一份声明的校验；两个成功分支均记录，不再按有无摘要筛掉文件。
2. 私有 Snapshot 只复制 RelativePath、Size、Sha1、Sha512、Md5、S3SinglePartETag、Category；不带无关 URL／网络状态。无摘要文件继续用原有本地 SHA-512 Freeze，不写回为伪上游摘要。
3. FrozenFiles 返回独立对象；PublishedLease 也复制构造输入。原计划、返回值和传入租约的对象随后被修改，都不能反向改变已接受的期望。
4. 最终 Verify 使用已有可取消 Matches，避免新增的大文件复验扩大取消等待。构造取消走原 catch 释放已开的句柄；已建立 guard 的取消仍由调用方原 using／Dispose 释放。

最终阶段先按原期望重新取得读租约并复验，再在实例同卷重命名前再次复验；通过该短提交窗口保持读租约。不会把共享文件重新散列成“当前内容就是正确”的新期望，也不延长整个资源下载等待阶段的锁。

发现外部改动时明确失败，不发布新实例；外部文件／目录和已有实例 JSON／原生设置保留。已正确完成的共享文件仍可供重试复用，不把保留可复用文件视为回滚错误。实例发布成功后的 Complete／ReleasePublishedClient 顺序保持，不因迟到取消反向宣告失败。

## 源码依据

以固定 PCL2 `5ef81e490ae46b1100d61e33d0183094c7a80ca8` 的 McInstallLoadersGet／ModDownload 组件支持库迁移、校验和安装阶段为核心，C# 参考 PCL-CE `915ac29795efbdf6373417389e181e1504117048` 对应组件／支持库逻辑和可取消流哈希。原始 Git 字节及 SHA-256 存于 `artifacts/runtime-publication-conflict/source/manifest.json`。本工具拥有自己的并行安装和原子发布边界，不声称上游也使用相同 PublishedLease 实现。

## 验证

新增 VB 专项 127 项：12 个真实安装冲突组合、8 个声明摘要快照、4 个所有权场景、SHA-1／SHA-512／MD5／S3 ETag、读租约阻写、原文件与设置保留、清理及重试。512 KiB+19 字节的构造／Verify 两处取消，旧实现均读满 524307 字节，候选首个 65536 字节块停止并保留原 token。六个标准算法别名和两个共享回调均显式验证恢复；原 hashless 检查保留。

冻结同一测试 EXE 仅替换旧 Core，12 个错误发布、8 个遗漏快照、4 个所有权及两处整文件取消均实际失败，不以缺少新 API 伪造红灯。添加恢复断言前的 120 项记录也保留，不覆盖首轮证据。

最终 Core 重新运行完整 VB 7814、旧 Beta 8 已编译宿主 7305、严格 API 零差异（979 public／1245 友元）、两资源／15 个 JSON／配置样本及 VS 2026 Debug。App 业务、检查和策略与 9909a21 相同；本轮只对新 EXE 运行单 EXE 冷启动 25／完整搜索 3240，不将上一批界面／动画数量伪称新 EXE 的结果。实际 DLL／EXE、内嵌依赖／七文档、源码和提交树绑定见 `artifacts/runtime-publication-conflict/validation.json`。
